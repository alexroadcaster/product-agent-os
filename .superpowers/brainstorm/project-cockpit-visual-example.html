Docs Pipeline Into Cockpit HTML

Как MkDocs и другие renderers пополняют cockpit без ручного редактирования HTML.

deterministic build no LLM tokens
1. Sources

Versioned project artifacts

Источники остаются diffable files, а не browser DOM.

  • docs/**/*.md
  • mkdocs.yml
  • AGENTS/PLAN/TEST/EVALS/RUNLOG
  • OpenAPI, DBML, PlantUML, Mermaid
2. Render Tools

MkDocs and contract viewers

Tools produce human-readable HTML/previews from typed source files.

  • MkDocs → site/
  • Swagger UI → OpenAPI view
  • PlantUML / Mermaid previews
  • DBML schema view
3. Scanner

Cockpit registry builder

Scanner reads both sources and rendered outputs, then normalizes metadata.

  • document-registry.json
  • diagram-registry.json
  • contract-registry.json
  • work-stats.json
4. Graph Packet

Graphology-compatible map

Relationships become nodes and edges, then sigma.js renders the browser graph.

  • nodes: docs, site pages, skills
  • edges: renders_to, verifies, backs
  • compact summary for Codex
  • full graph stays browser-side
5. Cockpit

Generated source-class HTML

HTML is regenerated from packet + graph + registries and can show stale state.

  • project-cockpit.html
  • project-cockpit.json
  • project-graph.json
  • manifest with source digests

Пополнение документации

Новая страница создаётся через approved patch: Markdown/contract source обновляется, `mkdocs.yml` получает nav entry, source registry фиксирует claim/evidence, MkDocs пересобирает `site/`, scanner обновляет registries и cockpit renderer пересобирает HTML.

Обратная связь из cockpit

Кнопки в cockpit не пишут в docs напрямую. Они создают proposal ledger entries: target files, owner, risk, approval status, verification command and rollback. После approval patch применяет изменения к source artifacts.

Staleness And Token Policy

Как cockpit остаётся актуальным и не раздувает Codex context.

Stale detection

Manifest stores hashes and mtimes for source artifacts and rendered outputs. If source changed after render, cockpit shows stale and suggests rebuild, not silent success.

Token control

MkDocs build, scanners and graph renderer consume zero LLM tokens. Codex reads only summary packet plus selected node details instead of loading all `site/` HTML.

Approval boundary

Adding docs through cockpit means creating a typed proposal, not browser-side editing. Source files remain reviewable through git diff and verification commands.

Graph Packet Shape

Будущий `project-code-graph.json` должен быть удобен и UI, и агенту.

Node types

`module`, `class`, `function`, `cli_entrypoint`, `test_case`, `fixture`, `template`, `doc_page`, `diagram`, `api_contract`, `database_model`.

Edge types

`imports`, `calls`, `reads`, `writes`, `renders`, `verifies`, `documents`, `generates`, `requires_approval`, `impacts`.

Confidence

`AST` for imports/symbols, `STATIC` for tests/templates/docs references, `INFERRED` only when synthesis links docs to code and must show reason/evidence.

Reference models

CodeGraph-style pre-indexed code intelligence for symbols/callers/impact, plus Graphify-style persistent graph, communities and confidence tags.

Token policy

Default prompt gets graph digest, hotspots, nearest neighbors and exact file spans. Full graph stays browser-side; source reads become intentional follow-ups.

Operational Signals

Какие метрики должны превращаться в warnings/proposals.

Stale generated site

Source docs count, `site/search/search_index.json`, rendered HTML count and manifest digests diverge. Action: propose MkDocs rebuild and update cockpit packet.

Verification age

Latest full verification is stored in TEST/RUNLOG/EVALS with timestamp and command. Action: show stale evidence if source files changed after the run.

Source policy gaps

Docs without `Source status:` or unsupported source claims create docs-maintainer proposals, not silent success badges.

What Not To Treat As Success

Anti-vanity rules for the metrics tab.

guardrails

Counts alone are not quality

More docs, more templates or more fixtures do not prove readiness without source status, verification evidence and owner-reviewed gaps.

Generated HTML alone is not proof

MkDocs output, Swagger UI and metrics reports are views. Cockpit must link to source artifacts and manifest freshness.

LLM judge score needs dataset context

No isolated score without trace intake, dataset quality, leakage checks, calibration summary and accepted-gap policy.
