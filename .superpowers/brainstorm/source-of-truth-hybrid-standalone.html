Variant C: Hybrid Project Cockpit

HTML becomes the user's canonical cockpit for project state, diagrams, documents, stats and graph navigation. Mutations still pass through typed ledgers, approval records and diffable backing artifacts.

User Source

Project Cockpit HTML

One panel for current project state: architecture diagrams, used documents, MkDocs routes, Swagger/OpenAPI, PlantUML, DBML, generated artifacts, metrics and pending decisions.

Allowed: inspect, filter, navigate, compare, create typed proposal.

Forbidden: silent direct mutation of docs or contracts.

Write Boundary

Typed Ledger / Patch Proposals

Every cockpit action becomes a structured intent: target files, owner, risk, approval state, verification command, rollback and generated patch plan.

This keeps auditability and prevents the dashboard from becoming an invisible editor.

Backing Stores

Durable Project Artifacts

AGENTS, REQUIREMENTS, PLAN, TEST, EVALS, RUNLOG, docs, source registry, diagrams and API/database contracts remain versioned stores.

Approved proposals sync back, then the cockpit regenerates.
