# Product-Agent OS — desktop design V2

Source status: project-authored design proposal based on current UI sources and public references, 13.11.2026. Status: needs_user_acceptance; application implementation remains planned.

## Что утверждаем

**Porcelain + Obsidian** — единая современная рабочая среда в светлой и тёмной теме. Компактные списки, выбранный объект рядом с контекстом, спокойная иерархия поверхностей, единые SVG-иконки и короткие осмысленные переходы. V2 охватывает все 14 разделов и вложенные вкладки. Подэкраны, выделенные из прежних длинных форм, обозначены как новая организация существующих возможностей.

Предлагается утвердить визуальную систему, компоновку, плотность и поведение состояний. Это ещё не разрешение на внедрение. Backend, API, модели данных, permissions, lifecycle, queue semantics, данные и работающий сервис не изменяются. Мобильная версия не разрабатывается.

## Причина реорганизации

По снимку и исходникам настройки совмещали общие параметры, подключение, 8 состояний и 23 перехода процесса, миграцию, версии, выполнение и очередь. Одновременное раскрытие одинаковых форм создаёт слишком длинную страницу. Большие одинаковые рамки и кнопки ослабляют иерархию. В задачах есть 8 вкладок, в сессиях — два уровня переключения; первые макеты этого полностью не показывали.

Текущий CSS уже содержит tokens, focus, responsive и overflow-защиту. Причину каждого переполнения нужно воспроизвести при внедрении: чтение исходников не доказывает все runtime-причины. V2 проверяется как отдельный дизайн-артефакт.

| Surface | `#FCFCFD` | `#1D222A` |
| Primary text | `#20242D` | `#EEF1F7` |
| Accent | `#3366F4` | `#90B4FF` |
| Семантика | Sage — завершено; amber — ожидание; coral — ошибка/опасность | Те же смыслы с отдельными контрастными парами |
| Типографика | System sans с кириллицей; controls 14px, reading 16px, title 24px | Та же геометрия; monospace только code/ID |
| Плотность | Строки около 40–44px, кнопки 32–36px, интервалы 4/8/12/16/24 | Та же геометрия |
| Глубина | Тонкие разделители, сдержанная тень у overlay | Более светлая поверхность выше canvas, без glow |

Точные tokens: [tokens.css](design/2026-11-13-v2/tokens.css). Таблица задаёт направление; фактические contrast receipts — в verification. Статус передаётся текстом и формой, а не одним цветом. Иконки преимущественно нейтральные; цвет помогает различить ресурс/состояние. Внешние font/icon dependencies не установлены.

## Оболочка и ширина

Навигация группируется по работе, ресурсам, контролю и служебным операциям; все исходные назначения сохраняются. Проект выбирается наверху sidebar. Подключение постоянно видно, технические детали раскрываются отдельно. Breadcrumb показывает контекст, заголовок — текущий объект.

Sidebar около 208–220px. На 1920px не растягиваем текст до края: пространство используется для списка и inspector. 1440px — основной рабочий режим. На 1280px вторичная панель перестраивается, а основной документ не расширяется. Нельзя скрывать недоступные controls через overflow:hidden и считать это исправлением.

Layout использует `minmax(0,1fr)`, `min-width:0` и переносы длинных путей. Локальный scroll допустим у графа, code/diff и широкой доски; он не расширяет body. Формы не требуют горизонтального scroll. Каталог образцов, theme/review toggles и contact sheet принадлежат инструменту утверждения дизайна, не продуктовому меню.

## Все разделы и вкладки

В реестре V2 **80 образцов: 78 продуктовых поверхностей и 2 лаборатории дизайна**. Каждая имеет светлую и тёмную версии. Это не 80 новых разделов приложения: 20 образцов соответствуют существующим вкладкам, 5 — видам, 34 — панелям, 1 — overlay; 18 предлагают новое расположение существующих controls; 2 служат только утверждению компонентов и motion.

Распределение: обзор 2, задачи 18, сессии 7, агенты 5, скиллы 9, карта 2, документы 3, проверки 2, автономность 3, решения 4, поиск 1, импорт 3, backup 2, настройки/процессы/выполнение 17, лаборатории 2. Список и inspector могут быть представлены вместе на одном образце; это сохраняет рабочий контекст.

| Раздел | Поверхности | Новая композиция |
| --- | --- | --- |
| Обзор | Состояние, источники, работа и требующие внимания объекты | Компактные группы существующих сведений; без вымышленных KPI |
| Задачи | Список/доска, создание, 8 вкладок, смена статуса, удаление, настройки и архив | Список+inspector; доска в своей области; редкие вкладки доступны без длинной горизонтальной полосы |
| Сессии | Работа/Полная доступная история; Чат/Контекст/Изменения; run profile, checks, questions, decision | Список сессий и основная область; контекст рядом, читаемый диалог сохраняется |
| Агенты | Каталог; Профиль/Редактирование/История/Активность; генерация | Master-detail; предложенный профиль отличается от сохранённого |
| Скиллы | Каталог; Профиль/Редактирование/История/Активность; discovery/import; requirements→draft→diff→Apply | Читатель и редактор разделены; Apply отдельным действием |
| Карта проекта | Граф/Список; фильтры; узел/source/occurrences/related tasks | Структура на графе, точный поиск в списке; stale/unresolved видны |

| Проверки | Каталог и подробный результат | Источник и результат рядом; check pass не равен owner acceptance |

### Задачи

Выбор строки открывает объект рядом. Заголовок, статус и основные metadata остаются сверху; ниже меняется вкладка. **Описание, Файлы, Приёмка, Комментарии, История, Вложения, Связи, Сессии** — отдельные содержательные образцы. При смене состояния видны ограничения и причина, где она требуется. Карточка не перемещается до подтверждения операции. Компоненты, версии, release policy, board columns и архив остаются в настройках задач; отдельные панели — реорганизация существующих controls.

### Сессии и evidence

Обсуждение, контекст и изменения связаны общей выбранной сессией. Code/diff прокручивается локально. Новые сообщения не отнимают scroll у читающего историю. Вопрос пользователя, решение и технический результат различаются визуально. Предлагаемое изменение документа отделено от сохранённого файла. Успешный тест не окрашивает весь проект в «готово».

### Настройки и процессы

Подключение показывает состояние, объяснение и доступное действие; технические сведения вторичны. Shutdown имеет отдельную область с исходным подтверждением.

В редакторе процесса список состояний/переходов отделён от формы выбранного объекта. Сохраняются ID, name, from/to, actors, required fields/checks, recipeId, success/failure states и user decision. Схема — дополнительный взгляд на ту же конфигурацию. Advanced recipes доступны.

Save draft, validate, discard, publication preview и публикация не объединяются. Миграция показывает версии, mapping всех состояний, причину и исходные условия остановки активных запусков. Версии/архив, выполнение цепочек, шаги/recovery и очередь получают собственные образцы. Всегда ясно, идёт ли редактирование, просмотр результата или разрешение действия.

## Компоненты и движение

Shortlist: sidebar/project switcher, dense row/table, segmented tabs, inspector, dropdown/tooltip, skeleton, inline spinner, determinate/indeterminate progress, empty/error/stale state, result button, file-drop target, disclosure, diff и evidence row. [Исследование](design/2026-11-13-v2/research.md) связывает каждый с источником.

Переходы короткие: hover/press 100–140ms, вкладки 160–180ms, inspector 200–240ms. Это проектные параметры, не измерения конкурентов. Shell не исчезает при каждом клике. Skeleton повторяет будущую геометрию; refresh сохраняет видимые данные. Успех показывается после подтверждения результата. Ошибка сохраняет ввод. Неизвестный прогресс не выдаётся за процент. Hold to publish не заменяет действующие gates.

`prefers-reduced-motion` отключает перемещения и декоративные циклы. Focus не ждёт анимации. Диалоги возвращают focus инициатору; tooltips доступны клавиатурой; важные действия не появляются только на hover. Лаборатория состояний использует симуляции и не изменяет приложение.

## Технологии и внедрение

Текущий apps/web/package.json содержит React/React DOM и Vite/TypeScript; UI/motion libraries в нём не заявлены. Минимальный маршрут — существующие React-компоненты + semantic tokens + CSS/WAAPI. shadcn, React Aria, Lucide и Motion — технические кандидаты, не установленный стек. View Transition API — только enhancement с функционально равным fallback. 3D, shader backgrounds, gooey menus, scroll hijacking и cinematic reveals не нужны рабочей среде.

Сначала согласуются две темы, плотность и компоновка; затем каждый screen ID и motion lab. После отдельного запроса на внедрение: baseline/tokens/shell → задачи и процессы как эталон → остальные разделы → согласованность motion/a11y → functional parity → приёмка. План V2 сохраняет 12 исходных задач, расширяя критерии до полного paired coverage. Новые действия, данные и разрешения добавлять нельзя.

## Критерии и пределы

Ноль потерянных действий/полей, одинаковые поверхности в обеих темах, отсутствие overflow shell, читаемые длинные подписи, keyboard/focus/reduced motion и сохранённые confirmations. Целевой контраст 4.5:1 для обычного текста, 3:1 для значимых UI-индикаторов. Фактически выполненные проверки и ограничения — в [verification](design/2026-11-13-v2/verification.md).

Не заявляем конкурентное превосходство, прирост скорости, полную WCAG-сертификацию и production readiness. Потенциальное преимущество PAOS — ясная совместная подача задачи, исполнения, evidence и решения. Его нужно проверять после внедрения на одинаковых рабочих сценариях.
