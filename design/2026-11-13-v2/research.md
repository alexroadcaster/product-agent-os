# Современный desktop UI: исследование и решения V2

Source status: first-party public references + project source audit, checked 13.11.2026; design proposal, not production implementation.

## Вывод

Главная проблема первого прохода — неполное покрытие рабочих сценариев и слишком слабая демонстрация поведения. V2 объединяет две равноценные темы, полный каталог экранов, отдельную лабораторию состояний и движения. Современность здесь создают пространственная последовательность, плотность информации, обратная связь и работа с ожиданием. Большое число эффектов само по себе не улучшает UX.

Исследование включает публичные сайты, официальные технические материалы, исходники текущего PAOS и визуальное наблюдение публичных страниц Ratio/bb. Закрытые кабинеты, пользовательские интервью и сравнительные измерения скорости не проводились. Времена анимации ниже — проектные предложения для PAOS, не измеренные параметры конкурентов.

## Подбор компонентов

Это спецификация приобретения/адаптации, а не список установленных библиотек. Прототип автономный, его элементы написаны локально. Перед внедрением проверяется совместимость с установленными зависимостями и текущими обработчиками.

| Компонент | Источник / материал | Где применяется | Что должен делать |
| --- | --- | --- | --- |
| Sidebar + Project switcher | [shadcn Sidebar](https://ui.shadcn.com/docs/components/sidebar), 21st Sidebar | Общая оболочка | Иконка 18px, текст, мягкое выделение; все 14 назначений доступны |
| Segmented control / tab pill | DesignBookmark Motion; [APG Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) | Список/доска, работа/история, вкладки объекта | Активный индикатор перемещается; стрелки/Home/End и aria-selected соответствуют содержимому |
| Master-detail inspector | [shadcn Sheet](https://ui.shadcn.com/docs/components/sheet) как поведенческий референс | Задачи, агенты, документы, решения | Список остаётся в контексте; узкий desktop переключает компоновку без расширения страницы |
| Dense table / row | [shadcn Data Table](https://ui.shadcn.com/docs/components/data-table) | Каталоги, история, версии | Статус+иконка+подпись; вторичные действия в строке; длинный текст переносится |
| Skeleton | [shadcn Skeleton](https://ui.shadcn.com/docs/components/skeleton) | Первичная загрузка списка/инспектора | Повторяет будущую геометрию; не заменяет уже прочитанные данные при refresh |
| Inline spinner / ProgressBar | [React Aria ProgressBar](https://react-aria.adobe.com/ProgressBar) | Проверка, импорт, backup | При известном объёме показывается фактический прогресс; иначе неопределённое ожидание с понятной подписью |
| Empty state | [shadcn Empty](https://ui.shadcn.com/docs/components/empty) | Пустой каталог / нет совпадений | Различает отсутствие данных, фильтр без результата, ошибку и отсутствие доступа |
| Morph copy / result button | DesignBookmark Copy button / Loading to success | Копирование и локальное подтверждение | Сохраняет ширину; состояние результата после фактического ответа, не по таймеру |
| Tooltip + dropdown | DesignBookmark Morph tooltip / Spring dropdown | Объяснение иконок, контекстное меню | Доступны с клавиатуры; tooltip не единственное место важной инструкции |
| File drop surface | DesignBookmark File drop | Импорт / вложения, только существующие маршруты | Drag-over выделяет цель; рядом остаётся обычный выбор файла; preview до применения |
| Disclosure / accordion | Стандартные HTML details + текущие формы | Технические сведения, recipe JSON, raw evidence | Раскрытие вторичных деталей без потери полей и ошибок |
| Evidence row + state badge | Собственная композиция из существующих PAOS полей | Проверки, решения, сессии | Источник, состояние, время и доступное действие; «проверено» и «принято» различаются |

Список названий DesignBookmark — названия обнаруженных примеров; подбор и адаптация относятся к проектному решению. Они не означают, что их код уже проверен или встроен.

## Motion как система

| Событие | Предложенная длительность | Изменение | Ограничение |
| --- | --- | --- | --- |
| Hover/focus/press | 100–140ms | Цвет, локальная opacity; press scale до .985 | Не смещать соседние controls, focus виден сразу |
| Переключение вкладки | 160–180ms | Общий индикатор; контент fade с перемещением до 4px | Не задерживать данные и клавиатуру ради эффекта |
| Открытие inspector | 200–240ms | Translate 12–16px + fade | Список и его scroll сохраняются |
| Menu/tooltip | 120–160ms | Scale .98→1 и fade от anchor | Без заметного bounce; закрытие быстрее открытия |
| Новый результат | 180ms | Мягкое локальное выделение строки | Не пересортировывать список неожиданно |
| Смена темы | 120–180ms | Цветовые tokens, без flash неверной темы | Без круговой full-screen маски |
| Layout при скрытии панели | 200–240ms | FLIP / shared layout при необходимости | Не анимировать каждую строку огромной таблицы |
| Skeleton | Мягкий pulse до 1.4s/cycle | Только область загрузки | При reduced motion статичный; не бесконечный декоративный shimmer |

Базовая кривая: cubic-bezier(.2,.8,.2,1). Spring нужен только небольшому индикатору, с минимальным overshoot. CSS transition подходит простым состояниям; Web Animations API — управляемым последовательностям. [Motion layout](https://motion.dev/docs/react-layout-animations) поддерживает shared layout через layoutId; [AnimatePresence](https://motion.dev/docs/react-animate-presence) — выход удаляемых элементов. Это кандидаты для React-внедрения, не причина устанавливать несколько animation engines.

[View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API) — опциональное progressive enhancement для смены контекста. Нужны feature detection и мгновенный функционально равный fallback. Нельзя связывать доступность маршрута с поддержкой анимации. [web.dev](https://web.dev/articles/animations-guide) рекомендует отдавать предпочтение transform/opacity и проверять затраты rendering; ширина/высота большой рабочей области не должны непрерывно пересчитываться ради эффекта.

При `prefers-reduced-motion` отключаются пространственные перемещения, pulse и декоративные повторы; смысл состояния остаётся текстом и иконкой. [Motion useReducedMotion](https://motion.dev/docs/react-use-reduced-motion) предоставляет соответствующий hook. [WCAG 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html) — критерий уровня AAA об отключении несущественной motion-анимации; его использование здесь не является заявлением полной сертификации WCAG.

## Ожидание и обратная связь

1. Сразу после действия: pressed/pending на самом control, блокируется только повтор той же операции. Оболочка остаётся доступной.
2. Быстрый ответ не должен мигать skeleton. Порог около 150–200ms — начальная гипотеза для измерений, не обязательная задержка завершения.
3. При первой загрузке дольше порога — skeleton формы будущего контента и понятная подпись. При повторном refresh — существующее содержимое и ненавязчивый локальный индикатор.
4. Неизвестный прогресс не показывается процентами. Счётчик «3 из 8» допустим только если такой объём действительно сообщает существующий источник. Прототип явно подписывает симуляцию.
5. Ошибка остаётся у действия; введённые поля не исчезают. Повтор использует существующий контракт, не скрытый автоматический retry опасной операции.
6. Stale/offline — отдельное состояние, а не empty. Пользователь видит, что читает последнюю доступную версию.
7. Успех возникает после подтверждения результата. Публикация, миграция, удаление, restore и автономность сохраняют существующие preview/confirmation/permission gates. Красивый Hold to publish не заменяет их.
8. Streaming показывает фактически поступивший ответ; искусственный typewriter поверх готового текста не нужен. Новые сообщения не отнимают scroll у читающего историю.

## Что ещё улучшает восприятие

- Content-first layout: локальная навигация вместо длинной страницы с десятками открытых форм; одна редактируемая сущность за раз.
- Progressive disclosure: технические поля и raw-format доступны в ожидаемом месте; ошибки внутри свёрнутой секции выводятся и в её заголовок.
- Continuity: выбор, фильтр, scroll и черновик переживают открытие соседней панели в пределах действующих правил. Сохранение черновика не становится автоматическим без контракта.
- Тематические иконки: ресурсы различаются формой и умеренным цветом; статусы всегда имеют текст. Emoji и случайные наборы разной толщины не используются.
- Типографика: системный sans с кириллицей, 14px control, 16px чтение, 24px заголовок; monospace только IDs/code. Внешние premium fonts не требуются.
- Граф: направленные связи и подписи для структуры; таблица для точного поиска; никакой 3D-карты ради эффекта. Лексическая связь не становится runtime-зависимостью.
- Честная evidence-иерархия PAOS: задача → сессия → файлы/проверки → решение доступны визуально рядом. Это потенциальное отличие в удобстве использования существующих возможностей, а не подтверждённое превосходство над конкурентами.

## Критерии оценки после внедрения

На одинаковых fixture-данных и viewport сравнить поиск задачи, доступ к любой из 8 вкладок, редактирование одного перехода, понимание состояния подключения, preview импорта и чтение результата проверки. Измерять число лишних открытий/возвратов, наличие горизонтальной прокрутки страницы, потерю контекста, ошибки понимания статуса и реальную отзывчивость. Нельзя обещать процент ускорения до сравнения. Цель: ноль потерянных действий/полей, ноль переполнений shell, полная keyboard-доступность, контраст 4.5:1 для обычного текста и 3:1 для значимых UI-границ/индикаторов, motion без блокировки действий. Производительность проверяется на настоящем React-приложении после отдельного внедрения.
