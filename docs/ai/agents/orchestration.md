Описанные тесты — маршруты проверки, не новый прогон; фактическая активация и human acceptance требуют отдельного evidence.

## Выбор и граница

[main.mts](https://github.com/alexroadcaster/product-agent-os/blob/61f6cd4cd048be478e88e2406c733f98b60bc434/apps/local-service/src/main.mts) создаёт App gateway и второй gateway, затем передаёт их в [route-selector.ts](https://github.com/alexroadcaster/product-agent-os/blob/61f6cd4cd048be478e88e2406c733f98b60bc434/apps/local-service/src/runtime/route-selector.ts). При отсутствии route и API key selector выбирает `codex_app_agent`; наличие `apiKey` без route выбирает `local_api_byok`. Очередь сериализует connect/disconnect/dispatch; при смене активного route требуется disconnect. Автоматического fallback между route нет. [LLM routes](../llm/routes.md) владеет деталями.

## App-agent: от подключения до результата

1. В UI выбирают App route. Он не становится attached только от открытия draft или окна Codex App. [app-agent-channel.mts](https://github.com/alexroadcaster/product-agent-os/blob/61f6cd4cd048be478e88e2406c733f98b60bc434/apps/local-service/src/runtime/app-agent-channel.mts) предоставляет отдельный per-instance loopback capability channel; browser cookie не даёт worker authority.
2. [app-agent-gateway.mts](https://github.com/alexroadcaster/product-agent-os/blob/61f6cd4cd048be478e88e2406c733f98b60bc434/apps/local-service/src/runtime/app-agent-gateway.mts) принимает attach только при выбранном route и ожидаемом hostIdentity. Worker получает lease с generation; heartbeat продлевает его. Host identity здесь attested доверенным вызывающим, а не криптографическое доказательство идентичности.
3. Для discussion/planning/execution создаётся project/session binding. Execution требует настроенного broker; project root identity проверяется. Send сохраняет queued job и возвращает его состояние. Consumer должен claim получить работу; повтор того же clientMessageId с конфликтующим payload отклоняется.
4. Claim фиксирует worker/generation и running; consumer может передавать progress и terminal report. Report idempotency ограничена ключом и digest. Итог agent_reported не является owner acceptance или доказательством выполненных проверок.
5. Stop у queued job может завершить его как interrupted; активному job ставится cancel_requested и запрашивается остановка broker. Подтверждение interrupted и завершение внешних операций — отдельные наблюдения. После рестарта или неизвестного исхода возможен recovery_required без автоматического replay.
