## Web graph

[service.mts](https://github.com/alexroadcaster/product-agent-os/blob/61f6cd4cd048be478e88e2406c733f98b60bc434/apps/local-service/src/code-index/service.mts) requires `revision` for graph/node/impact/source; missing or mismatched revision yields `GRAPH_REVISION_REQUIRED` / `GRAPH_REVISION_STALE`. Status separately returns fresh/stale/unavailable and coverage. Revision digests the file, parser and config manifest; the snapshot is in memory.

Graph query filters names/paths, edge types and neighbors to depth 3. Default page size is 50, maximum 100 nodes; incident edges are bounded at 100 and off-page endpoints return as contextNodes. `partial` indicates the result is not complete. An HMAC cursor binds project, revision and filters to an instance-random secret; persistence across restart is not promised.

Node impact returns directly incident edges and related tasks with `bounded_first_1000`, not a complete transitive blast radius. A source excerpt requires a fresh snapshot and checked file hash; default length is up to 2000, maximum 8000 characters with redaction. A stale source raises `GRAPH_SOURCE_STALE` instead.

## FUNC-02 — explicit task references and documents

Current lower source `apps/local-service/src/artifacts/references.mts` collects paths from `files`, `fileContexts`, `artifacts.reference` and legacy `artifactReferences`. Path normalization reuses F28: Windows separators become `/`, comparisons respect Windows case semantics, and traversal/absolute/URL/ADS syntax never becomes a local file reference. Duplicate field/path/revision tuples are removed; references from different fields retain provenance. Task titles and arbitrary prose are not semantic-impact evidence.

The document catalog links tasks to actually available source paths. A task whose path appears only in `artifacts.reference` is therefore found by the catalog `taskId` filter, and the document returns backlinks for explicitly related tasks. Legacy `files` and `artifactReferences` retain their behavior. A URL such as `https://…/docs/Guide.md` is not converted into local `docs/Guide.md` and does not create that relationship. Current registry root identity/policy remain authoritative; a stored task reference does not itself grant read permission.

`taskReferences` separates relationship state from document state:

| State | Meaning |
| --- | --- |
| `matching` | Expected task raw-byte SHA256 matches the observed source hash. |
| `stale` | The saved pin differs or the reference is explicitly stale; a fresh document does not automatically repair an older link. |
| `unknown` | An explicit path exists but no expected source revision was recorded. This is neither file absence nor matching. |
| `unavailable` | Source availability is not established or the reference is explicitly unavailable; an unavailable reader does not supply its body. |

The catalog may show a current document with `source.state=observed` while a task backlink remains `stale`. Separately, `ArtifactDocument.state` describes `available`/`stale`/`unavailable` for the document being read. When a task has multiple references, a compatible duplicate does not conceal an incompatible pin. Web graph impact uses the same explicit path references but compares pins to source hashes in its graph snapshot, returning `matching`/`stale`/`unknown`; graph state/revision are checked separately. This is not a new semantic call graph or a complete blast radius.

`resolveTaskReference` in `apps/local-service/src/task-manager/service.mts` first checks that the path belongs to the task, then performs an F28 read under current registry root/policy. Content requires a raw SHA256 pin: no pin yields `unavailable / revision_required`, mismatch yields `stale` without replacement content. Responses distinguish raw-byte `revision`, metadata/policy `fileRevision`, `rootIdentity` and `policyVersion`; a metadata pin must not masquerade as legacy `fileContexts.revision`. An optional expected `fileRevision` is checked separately. Missing/moved/deleted/excluded sources do not become available documents, read authority or automatically inferred rename targets. Document-only redaction preserves the original hash and does not authorize sensitive paths/private-key content.
