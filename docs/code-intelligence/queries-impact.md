## Web graph

Graph query фильтрует имя/путь, типы edges и соседей до depth 3. ## FUNC-02 — явные ссылки задачи и документы

Текущий lower source `apps/local-service/src/artifacts/references.mts` собирает ссылки из `files`, `fileContexts`, `artifacts.reference` и legacy `artifactReferences`. Нормализация путей переиспользует F28: Windows separators становятся `/`, path comparison учитывает Windows case semantics, traversal/absolute/URL/ADS syntax не становится локальным file reference. Дубликаты одного field/path/revision удаляются; ссылки разных полей сохраняют provenance. Название задачи и произвольный текст не используются как доказательство semantic impact.

Каталог документов связывает задачи с фактически доступным source path. Поэтому задача, у которой путь указан только в `artifacts.reference`, находится через catalog `taskId`, а документ возвращает backlinks всех явно связанных задач. Legacy `files` и `artifactReferences` сохраняют поведение. URL вроде `https://…/docs/Guide.md` не становится локальным `docs/Guide.md` и не создаёт такую связь. Current root identity и policy из registry остаются authority; сама запись task reference не разрешает чтение файла.

`taskReferences` отделяет состояние связи от состояния документа:

| State | Значение |
| --- | --- |
| `matching` | Ожидаемый raw-byte SHA256 задачи совпал с наблюдаемым hash source. |
| `stale` | Сохранённый pin отличается либо сама ссылка явно помечена stale; свежий документ не исправляет старую ссылку автоматически. |
| `unknown` | Явный path есть, но ожидаемый source revision не сохранён. Это не отсутствие файла и не matching. |
| `unavailable` | Источник не подтверждён доступным либо ссылка помечена unavailable; body не предоставляется через недоступный reader. |

Например, каталог может показывать текущий документ с `source.state=observed`, но его task backlink остаётся `stale`. Отдельно `ArtifactDocument.state` описывает `available`/`stale`/`unavailable` самого читаемого документа. При нескольких ссылках одной задачи несовместимый pin не скрывается совместимым дубликатом. Web graph impact использует те же explicit path references, но сравнивает pin с hash source своего graph snapshot и возвращает `matching`/`stale`/`unknown`; `graph.state` и его revision проверяются отдельно. Это не новый semantic call graph и не полный blast radius.

`resolveTaskReference` в `apps/local-service/src/task-manager/service.mts` сначала проверяет принадлежность пути задаче, затем выполняет F28 read в текущем registry root/policy. Для выдачи content нужен raw SHA256 pin: отсутствие pin даёт `unavailable / revision_required`, несовпадение — `stale` без replacement body. Ответ различает `revision` (raw bytes), `fileRevision` (metadata/policy), `rootIdentity` и `policyVersion`; переданный metadata pin нельзя выдавать за legacy `fileContexts.revision`. Optional expected `fileRevision` проверяется отдельно. Missing/moved/deleted/excluded source не превращается в доступный документ, право чтения или автоматически найденный rename target. Document-only redaction сохраняет original hash и не разрешает sensitive paths/private-key content.

Два новых regression scenarios в `tests/web/skill-generation-artifacts.test.mts` подтверждают structured-only backlinks/catalog task filter, legacy paths, URL exclusion, stale relationship, inventory policy denial и deleted source; manager/reference и inventory consumer checks входят в тот же receipt. ## FUNC-G04 / F34 — code-to-table impact и agent query

Schema ERD показывает metadata выбранной БД; code-to-table impact показывает статические места чтения/записи/DDL в разрешённых исходниках. Ни одна из этих проекций не доказывает runtime call graph, исполнение SQL или полноту динамических зависимостей. До реализации service закреплён corpus/matrix `tests/fixtures/func_g04/code-database/corpus.json`: JS/TS AST, literal SQL `FROM`/`JOIN`/`INSERT`/`UPDATE`/`DELETE`/`CREATE TABLE`/`ALTER TABLE RENAME`/`DROP TABLE`, Prisma v6 inline-schema subset, precision ≥1 и recall ≥0.9. Initial TypeScript 7.0.2 compiler-API attempt оказался setup failure: установленный package не экспортирует этот API. Выбран существующий public `rolldown/utils.parseSync` 1.2.18; ground truth не менялся для подгонки измерений.

`confirmed` требует прослеживаемого imported `node:sqlite.DatabaseSync(new URL(relativeLiteral, import.meta.url))` либо default `prisma-client-js` generator, единственного literal SQLite `file:` datasource и same-file traced `PrismaClient` delegate. Источник должен точно совпадать с выбранным source, а таблица — присутствовать в его schema snapshot. `@@map` связывает Prisma model с таблицей. Идентичное имя в другой БД остаётся inferred; env/cwd/dynamic SQL, shadowed/untraced receiver, constructor override, custom generator/config, ambiguous Prisma schema, CTE и foreign attached qualifier не становятся confirmed. Неприменённый rename/create target, отсутствующий в schema, — unresolved. Unsupported language, parse/depth/byte/link limits и missing source явно оставляют partial/unavailable. Quoted identifiers отделяются от value strings/comments; `query` содержит только структурную operation/table label, без SQL values, DSN или rows.

Factory `createCodeDatabase` предоставляет scan analyzer, status и query. Query требует `codeRevision` и `schemaRevision`; фильтры `table`, `path`, `operation`/`op`, `confidence`, `limit` 1–100 и HMAC cursor привязаны к обеим revisions, scan revision, inventory/root/policy scope и остальным фильтрам. Response/context ≤32 KiB; `nextCursor`, `truncated` и `contextBytes` сообщают границы. Test candidates — только конкретные разрешённые test paths с literal table mention: это кандидаты статической проверки, не доказательство выполнения/полноты тестов. Результаты сохраняются в profile namespace `project_code_database_v1` до 1 MiB; raw source bodies не сохраняются. Изменение code/schema/source-selection version, SQL file rename/delete, root/policy или parser fingerprint инвалидирует snapshot. После restart совместимые pins могут сохраниться, но memory-only code index требует восстановления, а старый instance cursor недействителен.

F28 checked reads сохраняют 512 KiB/file, 8 MiB aggregate, 1000 files; raw hashes, metadata revision, source selection и publication/cancel guard повторяются до profile CAS write и query response. Production parser работает в собственном Node child с пустым временным cwd, minimal environment, 128 MiB JS heap, watchdog thread и ≤10 s deadline; abort/timeout завершает только owned child, cleanup ждёт close. Input ≤20 MiB encoded JSON, output ≤1 MiB/1000 links. Это не native RSS limit: peak RSS и elapsed сам child измеряет до stdout; stage `data.metrics` возвращает `parserMaxRssKiB`/`parserMilliseconds` со scope, не включая их в persisted revision identity. ### F34 dictionary persistence

Поэтому словарь статических кандидатов тестов создаётся с null prototype; query читает только собственные свойства, а saved-state validation отклоняет массив вместо словаря. Production-service regression проверяет `__proto__`, `constructor` и `toString` через JSON persistence и restart сервиса: relative paths остаются строками. Неуспешный RED receipt сохранён; исправленный контракт входит в итоговый прогон658 тестов.
