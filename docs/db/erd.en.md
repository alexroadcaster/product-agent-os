## F33: explicitly selected offline SQLite schema map

The 2026-11-15 source slice `apps/local-service/src/database-map/` and `packages/contracts/database-map.ts` implements the backend for a selected local SQLite file. This is a target-project schema; the historical PAOS profile ERD and rejected tbls PoC above retain their boundaries. Shared HTTP/UI wiring and browser acceptance belong to separate F33 integration.

The registry owns root/policy. `status` discovers candidate metadata without opening SQLite; a candidate has not passed admission. `selectSource` requires relativePath, observed `expectedFileRevision` and profile CAS `expectedVersion`; clear revokes registration. The trusted constructor separately receives the PAOS profile DB path: canonical path/file identity prevents selecting it as a target. Sensitive paths, links/hardlinks, project exclude, gitignore, incomplete policy and root drift block admission; include cannot override hard denial. Generic Files reads continue to deny DB content.

Purpose-specific F28 admission reads only the 100-byte header through a checked handle. SQLite format3, rollback read/write format1 and absence of `-wal`, `-shm`, `-journal` are required. WAL header format2 is rejected even without sidecars; the application does not checkpoint, copy a whole database or run target SQL/scripts. Missing/corrupt/locked/unsupported sources receive explicit reasons.

Before `DatabaseSync`, a Windows helper holds root-to-file directory handles and the selected file with `FILE_SHARE_READ` only, checking reparse attributes, final handle paths and volume/file IDs. After readiness, Node repeats root/policy/stat checks. Only then does an owned Node child open SQLite with `readOnly:true`, `allowExtension:false`, `defensive:true`, `trusted_schema=OFF`, `query_only=ON`. An authorizer permits fixed metadata statements; user-row reads, ATTACH, DDL and extension functions are denied. The default helper uses fixed WindowsPowerShell without a policy bypass; unsupported hosts or refused leases report unavailable without a path-open fallback.

Metadata retains effective nullable separately from declared not-null, rowid alias/PK ordinal, generated/hidden columns, composite FK sequence and implicit parent PK resolution, and index direction/collation/expression markers. Views and virtual tables are listed without expansion and with partial reasons. Raw DDL, default expressions and rows are excluded. FK edges describe declared schema relations, not runtime usage; schema sources receive no invented line number.

Limits:128MiB source by stat, one active schema job,200objects/4096columns/1024FK mappings/4096index parts,5s child,512KiB metadata output,15s lease. The child has a64MiB JS heap and a separate16MiB watchdog; these are not OS RSS limits. Parent cancellation/lease loss terminates the owned child before release; the child watchdog independently bounds work and checks parent liveness. Cleanup does not affect target scripts or unrelated processes.

Profile namespace `project_database_schema_v1` stores CAS registration/state and at most two metadata snapshots. The F27 internal `schema` analyzer publishes a compact `snapshotRevision` reference rather than the whole schema in scan results. Pages support revision/filter/table/pagination and scoped Mermaid with safely encoded identifiers and escaped readable aliases/comments.
