## FUNC-32: tbls PoC and selected metadata adapter {#func-32-poc}

[PAOS-FUNC-32](../planning/functional-remediation-2026-11-15.en.md#task-paos-func-32) checks a separate synthetic target schema; it does not extend the PAOS schema above. Engine PoC decision on 2026-11-15: **`reject` tbls 1.96.1 as the authoritative SQLite metadata adapter**. The explicitly selected alternative for later F33 design is **Node 26 `node:sqlite`, read-only `table_xinfo` / `foreign_key_list` / `index_list`**. This is a PoC decision, without production target-DB integration or silent fallback.

Pinned version: [tbls v1.96.1](https://github.com/k1LoW/tbls/releases/tag/v1.96.1), commit `aa7e7326b3555205148c20cd4702ccdacf9af7c4`; Windows amd64 archive SHA-256 `ecd641e0d1ffde95350b1336cb03603c7f7fd8c7fc20a996323ea80d8594a5c6`, executable SHA-256 `331cba7eb566d4cd754ba3650abb9d573f483e0b598197e1060372e7fbc72dc3`. The official checksum was verified; no installer ran. Core [LICENSE](https://github.com/k1LoW/tbls/blob/v1.96.1/LICENSE) is MIT; complete [CREDITS](https://github.com/k1LoW/tbls/blob/v1.96.1/CREDITS) include separate dependency notices, including MPL-2.0 and dual-license notices. The complete binary must not be described as “MIT-only”; this PoC does not establish redistribution/legal clearance.

Observed rejection reasons:

- Generated column `parent.doubled` is absent from tbls JSON and Mermaid although `table_xinfo` and ground truth contain it. The pinned [SQLite driver](https://github.com/k1LoW/tbls/blob/v1.96.1/drivers/sqlite/sqlite.go) uses `table_info`; a successful exit is not complete-schema evidence.
- A valid SQLite table name containing a backtick causes tbls to fail; native read-only metadata retrieves it correctly. Canonical Mermaid encodes unsafe identifiers while original names remain in the object table; HTML/scripts cannot become diagram source.
- Tested Windows DSN forms containing `mode=ro`/`_query_only=1` created a missing database file. Therefore those parameters **do not establish read-only admission**. The guarded PoC adapter rejects missing, external, symbolic-linked and multi-linked files before launch; a direct CLI probe deliberately retained the negative evidence.

The corpus contains 6 objects: tables and a view, PK, nullable/NOT NULL, UNIQUE/index, composite FK, self-reference, no-FK and a generated column. The native snapshot contains 3 declared FKs and never infers an edge from `orphan.parent_id` naming. Schema fingerprint/revision, source kind, coverage and warnings belong to `paos_engine_poc_snapshot_v1`. Source-line anchors refer only to known synthetic DDL, not positions inside a database file. No user rows appear in the snapshot. Additional checks cover ignored target config, source-file preservation, missing/corrupt files, bounded lock failure, WAL and stale revision after schema changes during the extraction envelope.

Budgets pass, but cannot override correctness/read-only failures or establish production performance.

Ground truth and budgets were pinned before measurements in `tests/fixtures/func_g02/protocol.json`; raw receipts, source hashes, normalized snapshot, canonical `schema.mmd` and original DDL are retained in `.tmp/func-g02/f32/`. An initial edge-count oracle was corrected from 4 to 3; initial engine receipts remain available.

Normalization `sqlite_metadata_v2_effective_nullable` distinguishes effective `nullable` from the original metadata flag `notNullDeclared`. Under [SQLite rowid semantics](https://www.sqlite.org/lang_createtable.html#rowid), a single `INTEGER PRIMARY KEY` that aliases rowid never stores NULL even when `table_xinfo.notnull=0`. The adapter identifies an alias using the exact `INTEGER` type, `table_list.wr` and absence of an index with `index_list.origin=pk`; the historical inline `INTEGER PRIMARY KEY DESC` remains an ordinary nullable PK. Regression cases also cover `TEXT`/`INT` and composite PKs, table-level `PRIMARY KEY(id DESC)`, WITHOUT ROWID and STRICT. Synthetic NULL inserts verify only the test database; snapshots read metadata exclusively. Following independent review, only the selected Node adapter was corrected and its alternative snapshot regenerated from the same DDL. `result.json.alternativeRegeneration` records new hashes and the test receipt; previous snapshot/result copies have the `-before-nullability` suffix. Native benchmarks and the three rejection reasons were neither rerun nor changed.
