## FUNC-32: PoC tbls и выбранный metadata adapter {#func-32-poc}

[PAOS-FUNC-32](../planning/functional-remediation-2026-11-15.md#task-paos-func-32) проверяет отдельный synthetic target schema, а не расширяет схему PAOS выше. Решение engine PoC 15.11.2026: **`reject` tbls 1.96.1 как authoritative SQLite metadata adapter**. Для последующего design F33 явно выбран вариант **Node 26 `node:sqlite`, read-only `table_xinfo` / `foreign_key_list` / `index_list`**. Это решение PoC; production подключение target DB не реализовано, скрытого fallback нет.

Версия закреплена: [tbls v1.96.1](https://github.com/k1LoW/tbls/releases/tag/v1.96.1), commit `aa7e7326b3555205148c20cd4702ccdacf9af7c4`; Windows amd64 archive SHA-256 `ecd641e0d1ffde95350b1336cb03603c7f7fd8c7fc20a996323ea80d8594a5c6`, executable SHA-256 `331cba7eb566d4cd754ba3650abb9d573f483e0b598197e1060372e7fbc72dc3`. Проверен официальный checksum, installer не запускался. Основной [LICENSE](https://github.com/k1LoW/tbls/blob/v1.96.1/LICENSE) — MIT; полный [CREDITS](https://github.com/k1LoW/tbls/blob/v1.96.1/CREDITS) содержит отдельные notices зависимостей, включая MPL-2.0 и dual-license notices. Продукт не должен объявлять весь binary «MIT-only»; redistribution/legal clearance этим PoC не установлена.

Наблюдаемые причины reject:

- Generated column `parent.doubled` отсутствует в tbls JSON и Mermaid, хотя `table_xinfo` и ground truth её содержат. Закреплённый [SQLite driver](https://github.com/k1LoW/tbls/blob/v1.96.1/drivers/sqlite/sqlite.go) использует `table_info`; успешный exit не означает полную схему.
- Валидное SQLite имя таблицы с backtick вызывает ошибку tbls; read-only native metadata корректно получает объект. Canonical Mermaid кодирует небезопасные идентификаторы, а оригинальные имена остаются в object table; HTML/скрипты не становятся диаграммным кодом.
- Проверенные Windows DSN forms с `mode=ro`/`_query_only=1` создали отсутствующий файл БД. Поэтому read-only admission tbls этими параметрами **не доказана**. Guarded PoC adapter заранее отклоняет отсутствующий, внешний, symbolic-linked и multi-linked файл; прямой CLI probe намеренно сохранил отрицательное доказательство.

Corpus содержит 6 объектов: таблицы и view, PK, nullable/NOT NULL, UNIQUE/index, composite FK, self-reference, no-FK и generated column. Native snapshot содержит 3 declared FK и не выводит связь для `orphan.parent_id` из имени колонки. Schema fingerprint/revision, source kind, coverage и warnings входят в `paos_engine_poc_snapshot_v1`. Source-line anchors относятся только к известному synthetic DDL, а не к позиции внутри файла БД. В snapshot нет пользовательских строк. Дополнительно проверены target config ignore, неизменность исходного файла, missing/corrupt, bounded lock failure, WAL и stale revision при изменении схемы во время extraction envelope.

Измерения на Windows 10.0.26200 x64 / Node 26.5.0 / i7-12700H, 20 logical CPUs, по 3 запуска: tbls small JSON median **203.042 ms**, 200-table JSON median **367.996 ms**, largest response **271876 bytes**, maximum recorded native peak RSS **72.64 MiB**. Исходный Node in-process 200-table baseline median **16.892 ms** относится к adapter до исправления nullable. Отдельные 3 baseline-only запуска текущего adapter дали small median **1.063 ms** и 200-table median **5.945 ms**, maximum harness peak RSS **90204 KiB**; output metadata — 4068/104376 bytes. Команда `node tests/web/poc/func-g02/tbls-baseline.mts` обновляет только `result.json.baselineAfterNullabilityFix`; исходные `baselineRuns` и native receipts сохранены. Это разные startup scopes: baseline RSS относится к lifetime Node harness; CPU time и RSS напрямую не ранжируются. Данные укладываются в заданные budgets, но не отменяют correctness/read-only failures и не доказывают production performance.

Воспроизведение: `node --test tests/web/poc/func-g02/tbls-poc.test.mts` — **6/6 passed**. `node tests/web/poc/func-g02/tbls-poc.mts ABSOLUTE_PWSH_PATH` — **26 наблюдений**, 23 positive checks и 3 зафиксированных candidate failures, обосновывающих reject. Первичный ошибочный edge-count oracle исправлен с 4 на 3; первоначальные engine receipts сохранены.

Нормализация `sqlite_metadata_v2_effective_nullable` различает effective `nullable` и исходный metadata flag `notNullDeclared`. Согласно [SQLite rowid semantics](https://www.sqlite.org/lang_createtable.html#rowid), одиночный `INTEGER PRIMARY KEY`, являющийся rowid alias, не хранит NULL, даже когда `table_xinfo.notnull=0`. Adapter определяет alias по точному типу `INTEGER`, `table_list.wr` и отсутствию индекса с `index_list.origin=pk`; исторический inline `INTEGER PRIMARY KEY DESC` остаётся обычным nullable PK. Регрессия также проверяет `TEXT`/`INT` и composite PK, table-level `PRIMARY KEY(id DESC)`, WITHOUT ROWID и STRICT. Синтетические вставки NULL проверяют поведение только тестовой БД; snapshot получает исключительно metadata. После независимого review исправлен только выбранный Node adapter и пересоздан alternative snapshot из прежнего DDL. `result.json.alternativeRegeneration` содержит новые hashes и test receipt; предыдущие snapshot/result сохранены с суффиксом `-before-nullability`. Native benchmarks и три причины reject не запускались повторно и не изменялись.

Context7 `/k1low/tbls` использован для CLI/config/JSON/Mermaid contracts, `/websites/sqlite_docs` — для rowid/PRIMARY KEY semantics; отличие поведения закреплённой версии проверено actual binary и tag-pinned source. Изолированный UI-прототип и поддержка ER-семантики установленным tiny Mermaid проверены отдельно в общей приёмке FUNC-G02; они не подменяют эти engine measurements или human acceptance.

Общая изолированная приёмка прототипа завершена: browser22/22, включая фактический canonical erDiagram render, выбор таблиц/колонок, generated/effective-nullable metadata, filtered ER/export parity, source/Back и project isolation. Установленный tiny Mermaid поддержал этот fixture; local SVG/table fallback включается только после явной ошибки rendering. Это не внедряет F33 и не квалифицирует реальную target DB. ## F33: карта явно выбранной offline SQLite schema

Source slice от 15.11.2026: `apps/local-service/src/database-map/` и `packages/contracts/database-map.ts` реализуют backend для выбранного локального SQLite-файла. Это отдельная схема целевого проекта; историческая ERD профиля PAOS и rejected tbls PoC выше сохраняют свои границы. Shared HTTP/UI wiring и browser acceptance принадлежат отдельной интеграции F33.

Registry владеет root/policy. `status` перечисляет только metadata кандидатов, без открытия SQLite; кандидат ещё не прошёл admission. `selectSource` требует relativePath, observed `expectedFileRevision` и profile CAS `expectedVersion`; clear отзывает регистрацию. Trusted constructor отдельно получает путь PAOS profile DB: canonical path/file identity запрещают выбрать её как target. Secrets, ссылки/hardlinks, project exclude, gitignore, неполная policy и root drift блокируют admission; include не отменяет hard deny. Generic Files reader продолжает запрещать DB content.

Purpose-specific F28 admission читает только 100-byte header под checked handle. Требуются SQLite format3 и rollback read/write format1, отсутствие `-wal`, `-shm`, `-journal`. Даже WAL header format2 без sidecars отвергается; приложение не checkpoint-ит, не копирует целую БД и не запускает target SQL/scripts. Missing/corrupt/locked/unsupported источники получают явные reasons.

Перед `DatabaseSync` Windows helper удерживает root-to-file directory handles и selected file с `FILE_SHARE_READ` only, проверяет reparse attributes, final handle path и volume/file IDs. После readiness Node повторяет root/policy/stat checks. Только затем отдельный owned Node child открывает SQLite с `readOnly:true`, `allowExtension:false`, `defensive:true`, `trusted_schema=OFF`, `query_only=ON`. Authorizer разрешает фиксированные metadata statements; чтение user rows, ATTACH, DDL и extension functions запрещены. Default helper — fixed WindowsPowerShell без policy bypass; неподдерживаемый host или отказ lease даёт unavailable, без path-open fallback.

Metadata сохраняет effective nullable отдельно от declared not-null, rowid alias/PK ordinal, generated/hidden columns, composite FK sequence и implicit parent PK resolution, indexes с direction/collation/expression markers. Views и virtual tables перечисляются без expansion с partial reasons. Raw DDL, default expressions и строки данных не возвращаются. FK показывает declared schema relation, а не runtime usage; schema source не получает вымышленный номер строки.

Limits:128MiB source по stat, один активный schema job,200objects/4096columns/1024FK mappings/4096index parts,5s child,512KiB metadata output,15s lease. Child имеет JS heap64MiB и отдельный16MiB watchdog; это не OS RSS limit. Parent cancellation/lease loss завершает owned child до release; child watchdog независимо ограничивает работу и проверяет parent liveness. Очистка не затрагивает target scripts или чужие процессы.

Profile namespace `project_database_schema_v1` хранит CAS registration/state и максимум два metadata snapshots. Analyzer F27 internal `schema` публикует компактную ссылку `snapshotRevision`, а не всю schema в scan result. Pages поддерживают revision/filter/table/pagination и scoped Mermaid с безопасно кодированными identifiers и escaped читаемыми aliases/comments. Смена файла сохраняет совместимый старый результат как явно stale metadata; смена root/policy/source не даёт прочитать несовместимый snapshot. Changes сравнивает совместимые project/root/policy/path/normalization/adapter identities, отдаёт added/removed/changed; rename не угадывается. Без baseline — unavailable, при несовместимости нужен rebaseline. Source selection/revoke/CAS и publication guards запрещают поздний результат отменённой попытки.

Focused evidence находится в `.tmp/func-g04/f33/focused-native-final.log`; отдельный default-sandbox WinPS AuthorizationManager refusal сохранён в `windows-powershell-policy-denied.log`, native default WinPS qualification выполняется через разрешённый native executor без изменения policy. Независимый synthetic probe проверяет FSCTL_SET_REPARSE_POINT: при lease write-open получает sharing violation32, после release тот же probe создаёт junction. Проверены также write/rename/root/parent fences, existing writer, hardlink/junction, policy/header/sidecars, installed SQLite authorizer, реальные profile CAS snapshots/diff/revoke и workload200tables с неизменными target bytes/каталогом. Native RSS, browser/human acceptance и полное закрытие F33 этим backend evidence не заявлены.
