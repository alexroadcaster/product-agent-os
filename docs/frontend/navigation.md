## Вход и выбор проекта

После инициализации UI получает сессию, список проектов, настройки и состояние connection. Без сессии показывается форма pairing; ошибка показывается пользователю, а разделы меню отключены до `ready`. После входа сохраняется выбранный существующий проект либо выбирается первый. Если проекта нет, project-specific разделы показывают пустое состояние; Settings и портфель доступны отдельно. Header содержит breadcrumb, поиск, connection status и reload.

В исходном DG04 snapshot sidebar имел15 разделов, сгруппированных под Work, Knowledge, Management и Workspace; F26 добавляет независимый раздел `files`. Выбор проекта и раздела меняет React state; это не набор самостоятельных URL-маршрутов. Sidebar можно свернуть; механизм узкого layout закрывает меню после выбора, а Escape возвращает фокус к кнопке меню. `aria-current` отмечает активную страницу. Это описание механизма не расширяет desktop scope дизайна; подробности и ограничения — [accessibility](accessibility.md).

## FUNC-26 — раздел «Файлы» и reader

`ProjectFiles` использует `M1Api.projectFiles` и `projectFile`; backend `createProjectFiles(store)` получает root и policy из registry, а не из client input. Каталог доступен без готового graph/scan. Раскрытие папки запрашивает только её непосредственных детей; breadcrumbs и «Назад к каталогу» сохраняют путь. Пустые каталоги, unsupported extensions, binary и исключённые файлы остаются metadata с причинами. Фильтр Control-plane выбирает реальные пути; поиск явно ограничен текущим каталогом. Pagination показывает границы выборки; client display cap500 не выдаёт оставшиеся записи за отсутствующие.

Текст запрашивается отдельно по path и metadata revision. `available` содержит безопасный текст; `stale`, `unavailable`, `binary`, `too_large`, `unsupported` и `forbidden` содержат объяснение без source body, сохраняя каталог. HTML и scripts отображаются только как React text в `pre/code`. Reader ограничивает DOM окном80 строк, принимает file/line anchor и позволяет перейти к другой строке. Clipboard failure оставляет выделяемое поле для ручного копирования. Копирование пути не даёт права чтения; «Использовать в задаче» доступно только после успешного read и при подключённом callback.

File reference явно различает `revision`/`revisionKind=sha256` для legacy task source pin и `fileRevision` для metadata/policy pin; также передаются rootIdentity, policyVersion и line. Metadata revision нельзя записывать в legacy `fileContexts.revision` как content hash. Viewing/reference не разрешает dispatch: F10 повторно проверяет actual execution scope и limits. Hash navigation использует `project`, `file`, `line`; совместный App/router wiring и браузерную приёмку закрывает root FUNC-G03.

Смена проекта создаёт новый component scope и отменяет прежние list/read requests. Существующий `createLatestRequest` отклоняет superseded responses, а payload дополнительно проверяется по project/path. При уходе запросы останавливаются; polling здесь отсутствует. Metadata имеет observedAt/revision/policy; это explicit refresh/rescan, не обещание live watcher. Наблюдение изменений и общая свежесть принадлежат F18. Dirty task editor компонент Files не изменяет.

Focused команды: `node --test tests/web/project-files.test.mts tests/web/project-files-ui-model.test.mts` — **9/9,0skip** в текущем запуске. Проверены registered root без graph, lazy directory, rawSHA/reference separation, инертный HTML, typed stale/missing/binary/size/encoding/forbidden, display redaction/private-key denial, paging/filter/project isolation, реальные link/junction/root replacement, in-flight policy revocation и bounded line anchors. Service metadata RED/GREEN наблюдён. Это service/model evidence; RU/EN×themes, keyboard/focus, layout и фактический App путь требуют root-owned browser acceptance перед закрытием F26. ## FUNC-G04 — Files, Карта и База данных

В навигации проекта доступна «База данных»: «Схема», «Изменения», «Использование в коде». Settings → «База данных» содержит явный выбор offline SQLite из metadata candidates; discovery не открывает БД. В Схеме — searchable таблица/ERD, details PK/FK/index/views, revision/coverage/time/source и bounded pagination. ERD и accessible list используют одну страницу; выбор entity открывает те же details. Source binary DB не получает вымышленную строку исходника. Нет baseline — отдельное состояние; stale metadata сохраняется как прежнее наблюдение.

Карта имеет режимы зависимостей/символов, incoming/outgoing, bounded path, graph/Mermaid/list и evidence/source переход в Files. Files reader предлагает переход в Карту и раскрываемые связанные таблицы. Database Code usages и Map DB links позволяют перейти к source file/line или таблице. Дополнительные query panels монтируются при раскрытии/выборе вкладки, а не фоново во всех проектах. Ссылки project+file+line и project+database+dbtab поддерживают reload/back; поздние ответы другого проекта отбрасываются. RU/EN, обе темы и narrow layout сохраняют V3 компоненты; техническая проверка отделена от human acceptance.
