# План B2 — совет в Web и решение о поставке

Source status: local implementation evidence, synthetic browser qualification, approved synthetic actual-agent pilot and owner decision.

## Контракт и интерфейс {#route-and-ui}

| Задача | Результат |
| --- | --- |
| PMETH-19 | `POST /api/v1/projects/{projectId}/analysis/task-advice` находится за существующими проверками сессии, origin и CSRF. Сервер связывает сохранённую задачу с её ревизией, текущим инвентарём, стадией анализа и версией адаптера. |
| PMETH-20 | В **Задачи → Сводка → Рекомендация по задаче** отображаются следующий шаг, применимость и глубина методов, источники, причины и ограничения. Сведения о проекте остаются в **Обзор → Источники**. |
| PMETH-26 | Общая документация содержит синтетические сценарии CLI и Web на обоих языках. [Маршрут пользователя и оператора](../../product-agent-os/methodology-intelligence.md#task-advice) |

Проекция живёт во временном каталоге за пределами целевого проекта. До 200 файлов, 64 КиБ на файл и 2 МиБ общего содержимого. Нужные исходники читаются существующей политикой инвентаризации. Остальные разрешённые пути могут войти как метаданные. Содержимое чувствительных и запрещённых путей исключается. Изолированный Python-процесс получает ограниченный запрос через stdin, строит рекомендацию тем же кодом, что CLI, и возвращает только контракт. Команда теста должна соответствовать именованному Python unittest и быть указана в `TEST.md`. Совет не исполняет команды проекта.

API проверяет привязку ответа к проекту, задаче и ревизиям и сверяет хеши фактически прочитанных источников. Отмена завершает Python-процесс. При отсутствии доказательства API выдаёт явный статус, пустой или частичный вывод и причину. После выборочного сканирования схемы и базы кода используется сохранённая стадия анализа при актуальном инвентаре. Последняя ошибка анализа отображается явно. Дополнительное поле хранит наблюдение в существующей записи сканирования. Рекомендация не записывается.

## Синтетическая квалификация PMETH-23 {#synthetic-qualification}

- CLI и Web совпали по решениям, основаниям, требованиям и следующему шагу на эквивалентных входах. Критерий поведения сохранён как проверяемый инвариант адаптера задачи. Следующие шаги — `python -B -m unittest test_counter.CounterTest.test_increment_by_one` и сверка `guide.md` с `counter.py`.
- Тест `tests/web/project-task-advice.test.mts` проверил ограничение тела, сессию, origin, CSRF, чужую задачу, устаревшие источники и отказ Python. Неверные версия, проект, задача и ревизии отклонены. После отмены временный каталог очищен. Состояние проекта проверено до и после совета.
- Chromium через имеющийся Playwright прошёл 35 проверок по реальному API и сборке. RU/EN проверены в обеих темах, есть проверка ширины 400 px и вход по клавиатуре. Проверены загрузка, отсутствие анализа, частичность, отказ в доступе, чужой ответ и устаревание. Хеши целевых файлов совпали. Временный профиль очищен, внешние запросы отсутствовали. Артефакт `pmeth-b2-x1GxOd/result.json`, SHA-256 `96ae96b323a6ea1f28f69be81efd3124b57a68268ad6033606e21c507122b60e`. Хеши сборки и исходников записаны в отчёте.
- В среде исполнения первоначальный Chromium-процесс завершился при старте. Нативный повтор использовал тот же бинарник с включённой песочницей Chromium и одноразовым профилем. QA фиксирует ожидаемый 401 от проверки сессии до pairing и 403 в сценарии отказа.

## Пилот полезности PMETH-24 {#usefulness-pilot}

Владелец разрешил четыре изолированных прогона Codex на синтетических файлах. Модель и reasoning унаследованы одинаково. До запуска зафиксированы порядок, парные хеши, критерии первого шага, бюджет одной проверки и предел 120 секунд. Для сигнала пользы требовалось сохранить правильный первый выбор и убрать лишний шаг либо ускориться минимум на 20%.

| Сценарий | Без совета | С советом | Наблюдение |
| --- | --- | --- | --- |
| Backend-ошибка | Выбран именованный unittest, наблюдён `5 != 4`. Верхняя граница 36 с. | Тот же unittest и результат. Верхняя граница 24 с. | Один вызов чтения до выбора и одна проверка в обоих случаях. |
| Документация | Сверены `guide.md` и `counter.py`. Верхняя граница 30 с. | Та же сверка. Верхняя граница 43 с. | В обоих случаях обнаружено отсутствие описания прибавления двух. |

Все четыре прогона выбрали правильный первый шаг. Лишних действий, отмен совета, вмешательств владельца и изменений байтов не было. Верхние границы включают разный интервал до запуска и не подходят для сравнения скорости. Точное время, токены и стоимость прогона недоступны. Исправление, приёмка результата, повторные дефекты и стоимость ремонта не оценивались в этом read-only пилоте. По обоим типам задач польза `insufficient_evidence`. SHA-256 протокола `61a09239c428f74058893c3d95c1880e5da6741ae7080b1c12e50efabb5f48d3`, результатов — `956511674c9451bf8ef70ad3952b31d44bf10bb61e04ff10aa39d74b81e82d23`. Сохранены в `.tmp/pmeth-b2-pilot/`.

## Решение владельца PMETH-25 {#rollout-decision}

19.11.2026 владелец утвердил **`hold` для поставки** локальной ревизии `7a41dce01fdff0220427f66bed70d986361ca8559c6511298774d3ce48c7c448`. Техническая приёмка относится только к read-only Python-ошибкам и правкам документации в локальной сборке. Широкая полезность, понимание интерфейса человеком и профили расширения требуют отдельной проверки.

Отключение и откат выполняются удалением связанного UI и endpoint из локального пакета вместе с восстановлением совместимого pin. Существующий сканер читает прежний формат записи; введённое поле наблюдения не требует миграции. Целевые файлы и отчёты сохраняются. Повторный допуск выполняется на согласованном комплекте исходников, lock и бинарника. Установка, публикация, активные hooks и новые полномочия не входят в это решение.

| Открытый вопрос | Владелец и условие пересмотра |
| --- | --- |
| Польза, затраты модели, восприятие интерфейса | Владелец продукта согласует сопоставимую выборку, единое измерение времени, метрики затрат и проверку понимания. |
| Приватность, лицензирование и публикация | Владельцы продукта и выпуска проверяют минимизацию данных, права на поставку и каналы выпуска. |
| Активация в другой среде и расширение профиля | Владелец выпуска проверяет точный комплект платформы. Владелец профиля повторяет PMETH-23 на нужной ревизии. |
