## PMETH-10 и PMETH-11 {#architecture-evidence}

Команда `architecture` вызывает существующий F14 на профиле во временном каталоге, привязывает вывод к графу и инвентарю, проверяет наблюдаемые рёбра импорта. В результате видны путь, строка, правило, владелец, разрешённый `@x` API и точное legacy-исключение с причиной.

| Вход | Результат |
| --- | --- |
| Статическая страница, в том числе рядом с папкой `features` | Сохранить архитектуру. Папка сама по себе не влияет на решение. |
| Модульный legacy с наблюдаемыми публичными границами и зарегистрированным `@x` | Сохранить модульные границы. Без точной регистрации cross-slice импорт выделяется отдельно. |
| Растущий frontend с наблюдаемыми нарушениями на достижимом от страницы пути, частыми изменениями и умеренной ценой | Поэтапный FSD. При высокой цене или отсутствии связи с выбранной страницей предлагается укрепить границы. |
| Backend или native | Рекомендация по применимой архитектурной политике и наблюдаемый сигнал текущего стека. |
| Отсутствующий адаптер, неверная конфигурация, неизвестный импорт, junction или неподдерживаемый исходник | `partial` и причина. Предложение о миграции отсутствует. |

На одинаковых локальных файлах вызов прежней рекомендации B1 выполнялся перед B3 для трёх frontend-профилей. B1 одинаково обработал изменяемый путь у модульной и связанной страниц. F14 различил их по наблюдаемым импортам. В первоначальной проверке F14 для `TSImportType` отсутствовало ребро на первой строке. После исправления прошли import-type, re-export, literal dynamic import и локальный JSON `extends`, включая привязку alias к файлу определения. Пакетные и циклические extends, неизвестные alias, пути вне проекта и неподдерживаемые конструкции не повышают покрытие. F30 остаётся контрольным корпусом для импортов. ## PMETH-12 {#migration-proposal}

Для подходящей страницы вывод содержит baseline импортов, связанные нарушения, владельца, совместимый re-export, import ratchet и откат. Первый checkpoint ограничивается страницей и реально используемыми API. Вынос кода ниже требует наблюдаемого повторного использования и владельца. Проверка ratchet сравнивает количество нарушений по устойчивой паре путей и правилу. Перемещение строки само по себе не меняет результат. План допускает остановку после одного пилота и задаёт отдельные условия для PMETH-16 и профильного PMETH-23.

Область вывода — stdout и рабочая память. SHA-256 целевых файлов проверены до и после каждого синтетического CLI-вызова. Исходники проектов сохраняются при построении предложения. Для переноса, staging, применения и активации правил нужна отдельная выбранная область.
