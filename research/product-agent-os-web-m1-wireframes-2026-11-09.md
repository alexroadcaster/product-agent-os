# Product-Agent OS Web: единое окно и wireframes сессий

Source status: project-authored / proposed UX, Hallmark 2.0.0 applied to Markdown specification. Дата: 2026-11-09. Версия UX: **0.7**, status: **draft_for_review**. Product direction — PRD v0.7 §17; implementation not_started.

Актуальные wireframes единого окна. Они заменяют read-only M1 v0.1, сохранённый в историческом приложении. Это текстовые схемы интерфейса, без рамки браузера/ОС, CSS, HTML, нового PNG или работающего прототипа. Все примеры сообщений и PAOS-0101 ниже синтетические; они не являются текущими задачами, логами или метриками репозитория.

## 1. Hallmark: направление и материалы

Pre-flight: исходный каталог экранов задаёт адаптацию Rim, modern-minimal, системный sans с кириллицей, monospace только для кода/ID/измерений, тёплые нейтральные поверхности и один акцент. Root design.md/brand-spec не обнаружены; working Web implementation не является входом этой задачи. Материал — собственные требования и прежние концепты, без реальной переписки и telemetry. Сохраняются восемь вкладок, обе темы и RU/EN. Новое — полноценная рабочая сессия и проверяемые переходы между её частями.

Hallmark scope: app screen. Нет marketing hero, лимита 80 слов для рабочих данных, фотографий, декоративных KPI, карточки внутри карточки и reveal-анимаций. Theme deal не повторяется: продолжается выбранная система Rim, а не новый независимый дизайн. Небольшие радиусы и light mode — прежняя явная адаптация; дизайн не объявляется буквальным Rim.

Signature: сообщение, задача, действие агента, изменение и проверка соединены прямыми ссылками с сохранением контекста. Чат главный; служебные данные раскрываются по потребности. Плотность разная по функции: разговор свободнее, события и diff плотнее. Панели отделены тонкими линиями и поверхностями, без вложенных карточек.

Нормативный token contract: будущая реализация объявляет цвета/шрифты/spacing в :root и theme blocks; использует semantic tokens paper, panel, ink, muted, accent, accent-ink, focus, error, warning, success, rule, font-body, font-code. Существующая palette в каталоге экранов остаётся ориентиром, не доказанным contrast результатом. Focus — мгновенный; только opacity/transform motion с reduced-motion fallback; app shell overflow-x: clip, длинный code внутри собственной области; без gradients/glow, uppercase labels, emoji icons и декоративных status dots. Никакие CSS-файлы сейчас не создаются.

Hallmark pre-emit self-assessment (оценка дизайнера, не измеренная usability): P4/H4/E3/S4/R4; variety not_applicable для продолжения одной системы. Слабое место E — неиспытанная плотность панелей; решено переводить inspector в отдельную область до сжатия чата. CSS/render/contrast gates pending implementation, не заявляется Floor 0 FAIL.

Контекст проекта всегда виден. Поиск относится только к выбранному проекту; глобальный поиск требует явного переключения scope. Восемь destinations оправдывают sidebar. Решения не становятся девятой вкладкой: доступны из внимания, task/run и inline-request. Workflow — из Задач/настроек, автономность — из состояния работы/настроек.

Предлагаемые геометрические бюджеты (не результат browser проверки):

| Ширина viewport | Композиция |
| --- | --- |
| 1440 | Внешние поля 24; доступно 1392. Навигация 200, список сессий 216, чат 624, inspector 320, два промежутка по 16 |
| 1920 | Общий shell capped 1520 и центрирован, боковые поля 200; не добавлять колонок; prose чата имеет отдельную читабельную меру |
| 1200–1439 | Компактная навигация 56; sessions 216; inspector 320 только если чат остаётся не уже 560; иначе inspector переключает основную область |
| 960–1199 | Компактная nav; session list опционально; inspector открывается вместо чата с Back, не сжимает его |
| 320–959 | Nav/session list в drawer; одна рабочая область Чат / Контекст / Изменения; никакой потери функций; narrow viewport не обещает remote/mobile deployment |

Resize панелей только внутри min/max, keyboard alternative и «Сбросить ширину»; preference привязан к viewport class. Font body 16, UI labels на один шаг меньше, максимум два семейства. Controls 32–40 с hit target не меньше 44; coarse pointer 48. Точные значения проверяются при реализации RU/EN, zoom 200% и длинных путей. Страница не прокручивается горизонтально; diff/code/table могут иметь локальную прокрутку.

URL хранит project/session и безопасные view параметры: panel=tasks|agents|files|checks, selected run, file reference, event/message anchor, фильтры каталога. Никаких prompts, credentials, draft text или absolute paths в URL. Пример формы адреса: /p/:project/sessions/:session?panel=files&run=:run&file=:fileRef. Сервер проверяет принадлежность каждого ID проекту.

## 3. Каталог и новая сессия

### WF-02. S08: каталог сессий

```text
Сессии                                      [Новая сессия]
[Найти по названию или тексту]
[Все состояния] [Задача] [Агент] [Источник] [Архив]

Название            Состояние         Задачи        Последняя активность
Вход в проект       Требует решения   PAOS-0101     Время из источника
Обсуждение идеи     Без выполнения    Не связана    Время из источника

История: доступная часть     [Почему есть пропуски]
```

Сортировка по последней активности; фильтры active/awaiting decision/finished/archived и пагинация. Пустая история «В этом проекте ещё нет сессий» с New session; пустой результат поиска предлагает очистить фильтры. Unavailable source не выглядит как ноль сессий.

Новая сессия открывает composer без немедленного provider call. Переименование и archive не удаляют историю. Active session нельзя молча archive: предложить оставить активной либо остановить и дождаться результата; archive не равен stop. Fork создаёт новую сессию с явным источником и границей перенесённого контекста, только если capability подтверждена; иначе показано «Недоступно в этом подключении». Импорт внешних сессий отдельный flow, не обязательный старт M1.


Постоянный label «Сообщение», placeholder — пример формата, не единственный label. Enter — новая строка; Ctrl+Enter/Cmd+Enter — отправка вне IME composition; видимая подсказка. Перед отправкой видны mode, connection/payer и context scope. При отсутствии connection action открывает понятное исправление с сохранением draft; нет автоматического другой модели/account. Ready connection не является бессрочной гарантией entitlement.

### Состояние WF-03 перед первым Execution

Компактная сводка над composer, без дополнительного modal и повторного разрешения уже разрешённого scope:

```text
Следующий запуск: Выполнение
Целевая задача: [Выбрать из связанных задач]
PAOS-0101  Обработка ошибки входа       [Изменить]
Агент: builder, версия профиля из источника
Recipe: закреплённая версия / «Не применяется»
Подключение: выбранный runtime profile
Плательщик: подтверждённый источник    [Подключение]
Scope: src/login.ts, src/login.test.ts [Границы]
Приёмка: задана   Оценка: требуется    [Заполнить задачу]
[Отправить поручение]
```

Выбор target — отдельное действие, не следствие добавления task link. При отсутствии target/criteria/estimate отправка показывает inline ошибки и ссылки исправления; черновик остаётся. При неподтверждённой capability/authority/connection запуск недоступен с конкретной причиной и действием исправления. UI подставляет подтверждённые payer/версии либо «Неизвестно». Final validation выполняется при Send; новая версия или расширение scope требуют согласования по policy. Сводка не обходит runtime approval.

## 4. Чат и выполнение

### WF-04. S09: выполняющаяся задача

```text
Сессии             Авторизация проекта             Контекст  [Развернуть]
[Поиск]            PAOS-0101   Режим: Выполнение     [Задачи] [Агенты]
                                                   [Файлы]  [Проверки]
Авторизация        Пользователь
Обсуждение идеи    Добавь обработку ошибки входа.   Текущая задача
                                                   PAOS-0101
                   builder                         Обработка ошибки
                   Проверяю форму и обработчик.
                                                   Запуск: выполняется
                   Действие: прочитан файл          Исполнитель: builder
                   src/login.ts [Открыть событие]   [Открыть задачу]

                   [Есть новые события]            Оценка: из плана
                                                   Факт: из событий
                   Следующее сообщение
                   [                              ]
                   [Добавить в очередь] [Остановить запуск]
```

Это схема synthetic content, не текущий runtime. Сессия не заполнена bubbles для каждого tool token. Человеческие и agent messages — плоские блоки с автором, ролью и временем; timestamps с timezone доступны, длительность — HH:MM:SS. Группировать последовательные события можно, но исходные records остаются раскрываемыми. Порядок определяется source sequence, не временем прихода SSE.

Поведение transcript:

- При чтении внизу новые события следуют за потоком. При прокрутке вверх экран не прыгает; «Новые события» возвращает к последнему. Loading older сохраняет anchor и текущую позицию.
- Streaming message имеет partial-state; завершение не показано до receipt. Connection loss сохраняет последнюю подтверждённую часть и объясняет gap.
- Скрытый по privacy фрагмент, усечение по размеру и недоступный источник обозначаются разными labels. Hidden chain-of-thought не запрашивается и не рисуется.
- Текст агента не может создать approval-кнопку, поставить Done или изменить policy. Интерактивные actions появляются только из валидированного typed event.
- Markdown/code/file links безопасно отображаются; внешние ресурсы имеют явное назначение. Terminal output доступен read-only, без shell command box.
- Поиск по сессии показывает coverage; переход к событию сохраняет текущую позицию для Back. Copy копирует только показанное доступное содержание.
- Сообщение после ACK неизменно; редактирование отправленного текста означает новый corrective message или явный fork. Retry — новая попытка, исходная ошибка остаётся в истории.

### Composer: три режима и очередь

| Режим | Что разрешает UX | Что происходит при запуске |
| --- | --- | --- |
| Обсуждение | Уточнить идею, прочитать доступный контекст | Inference возможен, target writes запрещены policy |
| Планирование | Получить plan/proposal и превратить его в draft задачи | Task draft сохраняется только явным действием; target code не меняется |
| Выполнение | Работать над выбранной задачей в согласованном scope | До dispatch проверяются task, criteria, estimate, authority, capability и writer ownership |

Выбор режима не расширяет sandbox. Переключение режима/модели/агента во время run относится только к следующему запуску; активный run показывает pinned значения. По умолчанию follow-up помещается в видимую очередь, не вмешивается в активный turn. До dispatch его можно редактировать/удалять. Автоотправка очереди допустима лишь в уже разрешённом режиме/scope с повторной валидацией; иначе «Готово к отправке». M1 не обещает steer API; при будущем поддержанном вмешательстве отдельное действие сообщает эффект и ждёт ACK.

Нажатие Send с незаполненным обязательным полем показывает inline error и переводит focus к нему. Повторная отправка блокируется пока команда принимается; потеря ACK даёт «Проверяем отправку», не новый run. Draft и queue различаются. Локально сохранённые drafts имеют project/session binding, retention и явное исключение из provider context до отправки.

Context picker показывает явно добавленные файлы/фрагменты, source revision, тип вложения и причину включения. Контекст не ограничивается только attachments: отдельно видны разрешённые project roots и rules, по которым Codex может читать файлы. Удаление context chip исключает его из следующего turn, но не стирает ранее отправленное. Неподдерживаемый attachment блокирует отправку именно вложения с объяснением; секретный файл не добавляется автоматически.

## 5. Связанные задачи

### WF-05. S09 / inspector «Задачи»

```text
Задачи сессии                             [Связать]
Для текущего запуска
PAOS-0101  Task  Обработка ошибки входа
Статус задачи: В работе
Запуск: выполняется
[Открыть карточку]

Обсуждались в этой сессии
[Задача] [Причина связи] [Открыть]
[Выбрать целью следующего запуска]

[Создать задачу из выбранного сообщения]
```

Многие связанные задачи допустимы, но execution target ровно один на run. Новая link сама по себе не назначает target. Смена target во время выполнения не переносит существующий run/изменения; новый run только после остановки/завершения и новой проверки scope.

Создать из сообщения: preview типа/title/description/technical value/product value/criteria/estimate/risks, source message link, creator и initiator → пользователь редактирует → сохраняет draft. Никаких неподтверждённых оценок как факта. Epic/Task/Bug/UserStory/Sub-Task соблюдают parent rules PRD. Черновик может быть неполным; Ready/execute требует недостающие поля.

Inspector содержит краткую сводку и criteria, не полную тяжёлую форму. Все дополнительные поля, версии, components, attachments, Linked Issues, Comments и History доступны в S06/S07. «Открыть карточку» — навигация внутри PAOS с return-to-session; на широком экране допустим inline detail без нового route. Удалить связь не значит удалить task или историю её runs. Связь активного run неизменяема.

## 6. Работа агентов

### WF-06. S09 / inspector «Агенты»

```text
Агенты запуска                   [Текущий / Прошлые]
Роль             Состояние       Что делает
builder          Выполняется     Последнее событие
tester           В очереди       Проверка результата

Выбранный исполнитель
Профиль: закреплённая версия
Задача: PAOS-0101
[Инструкции] [Действия] [Дочерняя сессия]
Длительность: из событий
Использование: данные недоступны
```

Роли — примеры, а не обязательная цепочка. Обязательные поля участника: agent ID, display role, assignment, task, run/session links, pinned profile/skills, state, последний наблюдаемый шаг. Частота, outcomes, tokens/cost показываются только при источнике и периоде; подробная агрегированная статистика в S11.

Различать: «Назначен», «В очереди», «Работает», «Ждёт решения», «Завершил шаг», «Ошибка», «Остановлен», «Состояние неизвестно». Наличие профиля не доказывает запуск. “Что делает” берётся из tool/action/event, не из скрытого рассуждения или текста “я сейчас...”.

«Инструкции» открывает read-only snapshot, использованный run; ссылка на текущую редактируемую версию отдельно. Редактирование в S12 действует на последующие runs. Child session открывается в том же workspace с breadcrumb «Назад к родительской сессии». Остановка отдельного агента показывается только при подтверждённой runtime capability и объясняет влияние на группу; основной M1 Stop останавливает выбранный run, а не весь проект и не всех агентов.

## 7. Изменения файлов

### WF-07. S09: широкая область diff

```text
Авторизация проекта   PAOS-0101        [Вернуться к чату]
Изменения: [Текущий запуск] [Все связанные запуски]

Файлы                  src/login.ts
src/login.ts           [Единый diff] [Рядом] [Перенос строк]
  Изменён              Было: baseline revision
src/login.test.ts      Стало: наблюдаемая revision
  Создан               [Содержимое diff из источника]
                       Авторство: run / источник
                       [Проверки этого изменения]
                       [Связанное событие / источник]
```

В обычном inspector — список файлов с planned/actual operation и provenance; выбор расширяет Files в основной content вместо узкого нечитаемого diff. Чат сохраняет scroll/draft и остаётся доступен кнопкой Back. На узком экране unified diff по умолчанию.

| Вид | UI contract |
| --- | --- |
| Запланировано | Expected paths из task scope; это не сделанные изменения |
| Предложено | Preview ещё не применён; отдельный action и revision |
| Изменено | Наблюдаемый filesystem diff; нельзя требовать повторного Apply для уже записанного |
| Внешнее изменение | Не приписывать агенту; source revision conflict, перечитать/сравнить |
| Создано / удалено / переименовано | Явный тип операции; rename содержит old/new path |
| Binary / large / недоступно | Metadata и причина отсутствия text diff; нет пустого “изменений нет” |

Причинная подпись «Действие, изменившее файл» допустима только при подтверждённой correlation; иначе «Связанное событие» или «Авторство неизвестно». Фильтр по run не обещает точное authorship без source evidence. Working tree diff может включать изменения IDE; UI это показывает. Planned file вне фактического diff не считается completed. Изменение вне scope поднимает violation/decision по policy, а не автоматически расширяет задачу.

M1 viewer read-only. «Отменить изменения» не общая кнопка: rollback возможен лишь отдельным supported scoped proposal с guard на текущую revision. Stop не undo, accept result не commit, task Done не deploy. Git stage/commit/push и новый разрешённый apply не возникают из просмотра diff.

## 8. Запросы разрешений и вопросы

### WF-08. Inline runtime approval, тот же S09

```text
Запрос разрешения
Задача: PAOS-0101          Исполнитель: builder
Действие: из runtime request
Объект: проверенный путь / команда / адрес назначения
Причина: почему текущих полномочий недостаточно
Последствие: что изменится или куда будут отправлены данные
Область: только указанное действие
[Показать детали и ограничения]

[Отклонить] [Разрешить действие]
Состояние: ожидает вашего решения
```

Approval — плоская область transcript, не modal поверх другого modal и не card-in-card. В session header — текстовая ссылка «Требуется разрешение», переносит focus к запросу. При чтении старых сообщений экран не перехватывает focus; alert объявляет запрос и даёт переход. Inspector может показывать summary со ссылкой, но не вторую независимую кнопку Allow. S22 — общий inbox тех же сущностей.

| Тип | Что решает пользователь | Видимые действия |
| --- | --- | --- |
| Уточнение | Значение/требование/предпочтение | Ответить / пропустить, если optional |
| Продуктовое решение | Scope/plan/proposal | Принять предложение / вернуть / отклонить |
| Runtime permission | Конкретный запрос инструмента | Разрешить действие / отклонить |

Никакого общего «Одобрить всё». Product acceptance не передаётся как tool permission. Действующее bounded разрешение не спрашивается повторно. Persistent permission changes не входят в inline approval M1. Показываются actor, task/run, action, targets, effects, scope, freshness/expiry; raw payload только redacted advanced details. Request ID и process generation нужны сервису; человеку — причина и эффект.

Конкретный синтетический пример WF-08 (не реальная команда в этой задаче):

```text
Агент builder запрашивает разрешение
Задача PAOS-0101    Run: подтверждённый идентификатор
Действие: запустить локальную проверку
Команда: python -m pytest tests/test_login.py
Рабочая папка: корень подключённого проекта
Граница: один вызов; сеть не запрашивается
Эффект: исполнение кода тестов, возможна запись test cache
Причина: runtime policy требует разрешения этого действия
[Разрешить один вызов] [Отклонить] [Детали запроса]
```

Граница показана из runtime policy, а не выводится из слов pytest/тест. Если команда/cwd/effects отсутствуют или источник устарел, Allow недоступен: «Недостаточно данных для разрешения» / «Запрос устарел» и «Перечитать состояние». Отклонение/выход доступны. Если вызов уже покрыт authority, дополнительный запрос не создаётся.

### WF-09. Pending ACK / denied / stale

```text
Запрос разрешения
Вы выбрали: разрешить действие
Передаём решение…            Кнопки неактивны
────────────────────────────────────────────────────
После подтверждения:
Решение принято runtime      [Посмотреть действие]

Если источник изменился:
Запрос устарел. Действие не разрешено этим ответом.
[Перечитать состояние]
```

Нажатие Allow не показывает “выполнено”. Очередь pending не теряется при смене вкладки. Повторный ответ идемпотентен; если request решён в другом окне, показать принятое решение и actor/time, а не применить второе.

Deny оставляет отказ в истории; run может запросить альтернативу либо завершиться по фактическому runtime outcome. Запрещённое действие не выполняется, но deny не обязательно означает остановку всей задачи. Timeout/expired/restart/disconnected — соответствующие состояния; устаревшее согласие не переигрывается. При неясном ответе UI предлагает reconciliation, а не повторное Allow вслепую.

## 9. Результат и восстановление

### WF-10. Завершённый run, незавершённая задача

```text
Результат запуска
Исход: из runtime receipt
Что изменилось: сводка с источниками
[Файлы] [Проверки] [Артефакты]

Критерий задачи              Подтверждение
Ожидаемое поведение          Receipt / отсутствует
Регрессионная проверка      Receipt / не выполнялась

Остались вопросы: из evidence
[Вернуть на доработку] [Открыть приёмку задачи]
```

Completed, failed, interrupted различимы. “Проверки не выполнялись” не success. Owner decision связывается с scope/revision и не переписывает failed check. Если критерии не выполнены, Done не становится доступным лишь потому, что turn закончился. Manual close/cancel/reopen соблюдает PRD и показывается в S06; его receipt возвращается в сессию.

### WF-11. S28 / inline recovery

```text
Нужно восстановить состояние
Проект: Product-Agent OS     Задача: PAOS-0101
Последнее подтверждённое: событие из journal
После него результат действия неизвестен.

[История действий] [Наблюдаемые файлы] [Запросы решений]
[Проверить состояние] [Открыть сессию]

[Повторить чтение состояния] [Диагностика] [Вернуться]
Запуск по конфликтующим файлам недоступен: исход не установлен.

Если подтверждён сохранённый turn и runtime поддерживает resume:
[Возобновить подтверждённый turn]
Если turn завершён/остановлен, новый запуск — отдельное действие:

```

Обычный reconnect читает events/history, не повторяет run. Stop сначала “Остановка запрошена”, затем receipt; timeout — неизвестное состояние. При потере процесса новая работа по конфликтующим файлам не разрешается до проверки. После restart все прежние pending approvals пересматриваются. Expired token ведёт к connection recovery с сохранением draft/session, без автоматической смены аккаунта/плательщика.

Quit отличается от закрытия вкладки. При активном run диалог перечисляет затронутые задачи и предлагает «Остановить и выйти», «Оставить сервис работать», «Вернуться». Service background mode явный; выключение компьютера не поддерживает 24/7. Ошибка остановки остаётся видимой, не закрывает задачу как успешную.

## 12. Матрица состояний и доступность

Каждый data region (sessions list, transcript, task inspector, agents, files, checks, permissions) имеет loading, empty, error, full и дополнительный partial/unavailable. Локальная ошибка одного inspector не очищает чат.

| Область | Loading | Empty | Error / partial | Full |
| --- | --- | --- | --- | --- |
| Сессии | Skeleton строк | Новая сессия | Coverage + retry | Фильтры/строки/пагинация |
| Чат | Placeholder истории, draft сохранён | Composer и подсказка режима | Stream gap, не стирать старое | Message anchors и composer |
| Задачи | Skeleton summary | Связать/создать draft | Task source unavailable | Target run отдельно от links |
| Агенты | Placeholder assignments | Не назначены | Telemetry unavailable | Pinned roles и наблюдаемые steps |
| Файлы | Skeleton file list | Подтверждённо нет diff | Conflict/large/binary/unknown | Operations/revisions/diff |
| Проверки | Receipt placeholders | Не запускались | Failed check отдельно от load error | Outcomes и scope evidence |
| Разрешения | Проверяем состояние запроса | Нет ожидающих решений | Expired/stale/disconnected | Конкретный request и actions |

Control contract: default, hover, focus-visible, active, disabled, loading, error, success. Hover только для pointer; focus мгновенный, без layout shift. Disabled сообщает причину и технически недоступен; success основан на receipt. Для не-submit действий “success” означает выбранное/открытое состояние, не серверный успех. Busy submit сохраняет label и ширину, исключает duplicate.

Focus order: skip navigation → заголовок/текущий project → список сессий → transcript → composer → inspector. Panels имеют accessible names; клавиатурой доступны resize, tabs, menus, file operations и transitions. Модальное подтверждение destructive action удерживает focus, Escape отменяет, закрытие возвращает инициатору. Обычный inspector не модален и не блокирует чат.

Streaming chunks не объявляются screen reader посимвольно: live region сообщает meaningful state и завершённый блок с ограниченной частотой. Новое permission событие объявляется, но focus не крадётся. Смена tabs и Back сохраняют anchor. 200% zoom не отрезает composer/actions; системная клавиатура не перекрывает Send/Stop. Browser, contrast и assistive-technology проверка пока pending.


## 1. Пользовательский результат и граница M1

M1 помогает человеку ответить на четыре вопроса:

1. Над каким проектом и задачей я работаю?
2. Что требует внимания и почему?
3. Чем подтверждается состояние задачи?
4. Где первичный источник и насколько свежи сведения?

Основной пользователь — technical founder / product engineer, возвращающийся к существующему репозиторию после перерыва. Secondary user — AI Engineer, проверяющий состояние перед продолжением работы. Интерфейс должен быть полезен без чтения структуры папок и без знания имён REQUIREMENTS.md / PLAN.md / RUNLOG.md.

**Рабочее название M1: «Обзор проекта и подтверждения».** Успешный результат сессии — пользователь правильно понял состояние и выбрал следующий шаг, а не изменил task status.

### Разрешённые действия

| Категория | M1 |
| --- | --- |
| Читать | Overview, поддерживаемые задачи, документы, вопросы/блокеры, существующие check receipts |
| Искать | Локальный поиск в разрешённом индексе текущего проекта |
| Навигация | Drill-down, breadcrumbs, фильтры, ссылки на сущности |
| Обновлять представление | Bounded scan/refresh, отмена чтения, восстановление подключения |
| Локальная персонализация | Зарегистрировать/убрать project root из Web registry; сохранить view preferences |
| Изменять target | Нет: редактирование документов, task status, approvals и scaffolding исключены |
| Исполнять | Нет: Codex runs, tests, shell, Git, provider calls и deployment исключены |

Read-only относится к файлам проекта. Registry/cache/view preferences принадлежат локальному Web service; их запись нужна уже в M1. «Обновить сведения» перечитывает источники и **не запускает проверки**. «Убрать из списка» не удаляет папку проекта.

Нет composer чата, кнопок «Начать», «Одобрить», «Применить», «Принять результат», «Создать задачу». Не показывать их постоянными disabled-заглушками M2/M3. Если прочитан существующий pending approval, это историческая/источниковая запись; выполнить approval из M1 нельзя.

### 2.3 Основной shell

- Левая навигация 208 px: четыре раздела; внизу «Все проекты» и «Настройки».

## 3. Основной пользовательский путь

### J01. Вернуться в проект и понять, можно ли продолжать

Синтетический пример: проект «Atlas Notes», задача TASK-17 «Поиск по заметкам». Source говорит «В работе». Сохранённая проверка прошла на r12, текущий relevant source — r13. Есть записанный блокер «Не определено поведение пустого запроса».

| Шаг | Экран | Пользователь видит / делает | Результат |
| --- | --- | --- | --- |
| 1 | W01 Проекты | Открывает Atlas Notes; рядом дата последнего чтения | Выбран явный workspace, нет автоматического execution |
| 2 | W03 Обзор | «Требует внимания: поведение пустого запроса»; отдельно «Проверки относятся к прошлой версии» | За первый scan понимает проблему и предел evidence |
| 3 | W05 Задача | Нажимает «Открыть задачу», читает результат, acceptance, blocker source | Понимает, какое решение нужно; M1 не отвечает за пользователя |
| 4 | W09 Receipt | Открывает «Проверка r12» | Видит passed в прошлом и отсутствие подтверждения r13 |
| 5 | W06 Документ | Открывает связанный раздел требований | Получает точную формулировку и происхождение |
| 6 | W05 / W03 | Возвращается Back | Сохранились фильтры/позиция, не потерян контекст |

Finish: пользователь может сказать «TASK-17 в работе; нужно уточнить пустой запрос; проверка новой версии не подтверждена; источник — требования, раздел 3». В M1 он продолжает инженерную работу в существующем рабочем инструменте вне Web; Web не запускает Codex.

Не требовать прохода по всем экранам. Если Overview уже даёт достаточный ответ, пользователь может закончить на шаге 2. Основной inspection path — Overview → Task → Evidence, source viewer — углубление по необходимости.

### J02. Первый вход

Проекты empty → «Подключить папку» → показать scope чтения → read-only scan → Overview. Root без PAOS: доступны найденные документы, gaps объяснены; нет скрытого создания control plane.

### J03. Найти документ

Из любого project screen → поиск → выбрать результат → документ с подсветкой раздела → Back к выдаче с прежним query. При неизвестном формате задач поиск документов остаётся полезным.

### J04. Вернуться после изменения файлов в IDE

W05 открыт на snapshot S1 → reader обнаружил новое source состояние → «Есть изменения в источниках» → «Обновить сведения» → S2. Старый receipt не становится current. Выбранная задача остаётся; удалённая задача показывает unavailable, а не переход на другую карточку.

### J05. Нет связи с локальным сервисом

Оставить уже загруженные данные с датой → показать «Нет связи с локальным сервисом» → отключить refresh/новое чтение → «Повторить подключение». После reconnect запросить новый snapshot; project selection не переключать. Это локальное соединение, не интернет/provider status.

## 11. Семантика статусов, визуальная иерархия и обновления

### 11.1 Независимые измерения

| Что отображаем | Пример понятного label | Что label не означает |
| --- | --- | --- |
| Source state | «По источнику: В работе» | Что сейчас реально запущен agent |
| Check outcome | «Проверка прошла» | Что текущая версия проверена |
| Applicability | «Для прошлой версии» | Что исходная проверка провалилась |
| Coverage | «Частичные данные» | Что проект частично готов |
| Connectivity | «Нет связи с локальным сервисом» | Что пользователь offline в интернете |
| Owner decision | «По записи: принято с ограничениями» | Release authorization |

Date display: абсолютные дата/время и local timezone в details; «5 минут назад» — дополнение, не единственное время. Unknown timestamp обозначается явно. Freshness чтения и freshness проверки расположены у соответствующего объекта.

### 11.2 Color-role ledger

| Роль | Treatment | Дополнительная encoding |
| --- | --- | --- |
| Контекст | Нейтральный фон/текст, тонкие границы | Заголовки и группировка |
| Primary navigation/action | Один синий акцент | Button label, underline/selected marker |
| Focus | Контрастный outline | Отдельно от selected state |
| Внимание / stale / partial | Янтарный акцент | Icon + точный label, не один цвет |
| Failed / blocked access | Красный акцент | Error title и понятная причина |
| Passed receipt | Зелёный только у outcome | «Прошла», рядом applicability |
| Unknown / unsupported | Нейтральная штриховка/outline при необходимости | «Не определено» / «Не поддержано» |

Точные hex/font family не фиксируются low-fidelity wireframes. Проверить contrast/grayscale в следующем visual pass. Ни вся карточка, ни проект не становятся зелёными по одному passed check. Минимум ornamental графики; charts не нужны, пока задача решается текстом и сравнимыми строками.

### 11.3 Refresh contract

M1 использует snapshots; источник freshness — local reader. Proposed update модель: read при открытии workspace, manual refresh, change notification если watcher поддержан. Capability fallback — manual refresh с явным «Автообнаружение изменений недоступно». Не маркировать это Live.

Новая revision показывается notice без внезапной перестановки строк/фокуса. По explicit refresh набор view обновляется согласованно, latest observedAt меняется только после успешного чтения. Старый snapshot остаётся видимым и подписанным во время обновления. Mixed revisions в частичном snapshot имеют item-level stamps.

Reconnect получает authoritative snapshot; dedup updates, workspace isolation. Cursor replay — transport detail из архитектуры, не новая пользовательская кнопка. Hidden tab не требует постоянного polling; при возвращении — проверить актуальность, сохранить selection. Low-bandwidth/narrow режим не загружает все document bodies заранее.

Proposed density budget: Overview ≤3 task rows + ≤3 receipts, task list page 25 rows, viewer один выбранный document. Ограничение document size задаёт SourceReader; UI честно показывает truncation. Это проектные limits, не измеренная производительность. Fallback для большой коллекции — paginated list и поиск, не graph/canvas.

## 12. Empty, error и degraded states

| State / где | Текст | Primary action | Сохранение контекста |
| --- | --- | --- | --- |
| Нет проектов / W01 | «Подключите существующий проект» | Подключить папку | Нет false loading |
| Root отсутствует / W02 | «Папка не найдена. Проверьте путь» | Исправить путь | Сохранить ввод |
| Access denied / W02 | «Эта папка недоступна для чтения» | Выбрать другой путь | Не предлагать disable protection |
| Scan loading / W02/W03 | «Читаем доступные документы» | Отменить чтение | Без invented progress percent |
| Partial / W03 | «Часть источников не удалось прочитать» | Посмотреть ограничения | Доступные данные остаются |
| Нет PAOS source / W03 | «Задачи пока не распознаны. Найдены документы» | Открыть документы | Нет автосоздания инфраструктуры |
| Empty filter / W04 | «Нет задач с такими фильтрами» | Сбросить фильтры | Не путать с пустым проектом |
| Source conflict / W05 | «Источники расходятся в состоянии задачи» | Сравнить записи | Оба source refs, без auto-resolve |
| Stale / W09 | «Результат относится к прошлой версии» | Открыть задачу | Historical outcome остаётся |
| Evidence missing / W05/W08 | «Подтверждения не найдены» | Открыть источники задачи | Не писать «Проверка провалена» |
| Removed item / detail | «Запись больше недоступна в текущих источниках» | К списку | ID и context, без redirect на соседнюю |
| Disconnected / все | «Нет связи с локальным сервисом. Показаны сведения от…» | Повторить подключение | Только уже загруженные разрешённые данные |
| Session expired / все | «Локальная сессия завершена» | Открыть через launcher | Скрыть private content до auth; без вечного offline access |
| Unsupported/truncated / W06 | «Этот формат не поддержан» / «Показан фрагмент» | Посмотреть доступные сведения | Не download bypass |
| No search result / W07 | «Совпадений нет в доступных данных» | Сбросить фильтры | Query и coverage сохраняются |

Conflict state snippet:

```text
! Состояние TASK-17 не определено однозначно
  План / запись TASK-17: «В работе»
  Второй поддерживаемый источник: «Завершено»
  [Открыть первую запись] [Открыть вторую запись]
  Даты чтения не определяют, какой источник главнее.
```

Disconnected и expired session принципиально различаются: доступ к cache требует действующей авторизации. Read-only не делает private documents публичными.

## 13. Навигация, URL, Back и persistence

Все маршруты proposed; имена paths не публичный реализованный API.

| Экран | Route shape | URL state |
| --- | --- | --- |
| W01 | /projects | Только sort, без local root |
| W03 | /w/{workspaceId}/overview | Ничего лишнего |
| W04 | /w/{workspaceId}/tasks | state, attention, sort, page |
| W05 | /w/{workspaceId}/tasks/{taskId} | tab=summary/documents/checks |
| W06 каталог | /w/{workspaceId}/documents | kind, page |
| W06 reader | /w/{workspaceId}/documents/{artifactId} | mode=document/source, section anchor |
| W08 | /w/{workspaceId}/checks | taskId, outcome, applicability, page |
| W09 | /w/{workspaceId}/checks/{evidenceId} | Details section при необходимости |
| W10 | /settings | Без secret/config values |

Search query и абсолютные paths не пишутся в URL. IDs opaque, наличие ID не предоставляет доступ. Unknown/invalid URL params сбрасываются к safe defaults с notice; неизвестный workspace → «Проект не подключён здесь», без попытки открыть path из URL.

Back возвращает previous route + tab/filter/scroll, а не всегда Overview. Breadcrumb «Задачи» ведёт список; контекстная «← К задаче» в reader возвращает к originating task. Открытие shared local link без history использует fallback в родительский раздел.

Local preferences: последний workspace и view state, scoped per workspace. Search query/temporary selection — session memory; document contents не localStorage. Copy link не экспортирует данные и не обещает доступ другому человеку. Browser refresh восстанавливает route при valid session; expired item показывает unavailable. Дубликаты открытия проекта не создают дубликаты registry.

M1 не включает PDF/export отчёта. Выходной артефакт этой задачи — Markdown, который можно читать без renderer. Если позже появится screenshot/export, он обязан сохранять источник, дату, coverage и stale label; скрытые hover details не считаются достаточным доказательством.

## 14. Accessibility и content contract

- Четыре nav items имеют текстовые labels и active marker; существует skip-to-content.
- Semantic headings, tables и links; статус объявляется словами, не только цветом.
- Tab/Shift+Tab достигают всех actions; Enter/Space по роли. Dialog закрывается Esc, focus возвращается trigger.
- Route transition переводит focus на main heading, Back восстанавливает прошлую позицию; refresh не крадёт focus.
- Status updates объявляются кратко в polite live region; reconnect retry не озвучивается каждую секунду.
- Browser zoom 200% и narrow layout проверяются будущим UI QA; большой текст не обрезается без доступного полного значения.
- Reduced-motion: никаких обязательных animations; scan progress имеет статичный текст.
- Для каждого empty/error есть доступный next action; no hover-only tooltips.
- Русские labels, canonical технические идентификаторы сохранены в source/detail. «Подтверждения» объясняется рядом конкретной проверкой, не длинным onboarding.
- В production UI не показывать lifecycle marker, schemaVersion, internal task IDs governance или термины control-plane без нужды пользователя. Технические digests, commands и source paths доступны в provenance details.
- В M1 нет sensor permissions, system notifications и remote images без explicit user action.

Это acceptance targets, а не измеренное соответствие accessibility стандарту. Конкретные standard-dependent thresholds требуют проверки актуального стандарта на этапе visual/implementation review; здесь новые compliance claims не делаются.

## 16. Применение Build Web Data Visualization

Analytical job: orientation/monitoring и inspection evidence в project workspace. Data shape: task/document tables, source metadata, snapshots и typed receipts. Artifact family: текстовые low-fidelity wireframes с annotated flows; charts/3D/animation не нужны.

Primary route: `data-visualization → dashboards-and-real-time-visualization`; responsive reference `mobile-first-responsive-visualization`. Fallback: простые списки и source viewer при unsupported task projection. Plugin использован для hierarchy, direct labels, freshness/partial states, progressive disclosure, URL/session state и narrow/mobile reading path.

Reading order: insight («требует внимания») → immediate evidence (task state + receipt applicability) → source details → secondary controls. Focal accent один; unknown и stale не скрыты. Specialist pass выполнен локально одним агентом, без delegation. Высокодетализированные visual concepts/image generation не заказывались; Markdown wireframes покрывают требуемый low-fidelity этап.

Стек не переоценивается этим документом; опираемся на предложенный local SPA из архитектуры. Новые внешние facts, market estimates и runtime capability claims не добавлены. Источники — существующие проектные документы; skill является методом проектирования, не evidence реализации продукта.
