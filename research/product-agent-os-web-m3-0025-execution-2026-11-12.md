Термины checkpoint, run, attempt, cancel ACK и recovery trace к PAOS-0025/API `/execution-recipes/:id/{resume,reconcile}` и этим owners. Отдельный DDD scaffold не нужен; architecture/ADR/API/runbook сведения находятся здесь и в contracts/tests. ## Реализованный контракт и операторский путь

Existing authenticated `GET /projects/:id/execution-recipes[/:executionId]` дополнен `recovery` для paused/recovery_required/cancel_requested и `recoveryDecisions` для истории. Browser-safe checkpoint имеет `checkpoint`, `canResume`, `canCancel`, `runId`, `childState`; frozen instruction bytes не передаются. Checkpoint names: not_dispatched, processed, terminal_result, unresolved, interrupted, rejected_admission. `canResume` характеризует сохранённое evidence; текущие policy/scope/root/binding/artifacts повторно проверяются при действии.

Existing `POST /projects/:id/execution-recipes/:id/resume` с revision/authority epoch/idempotency key теперь допускает paused/recovery_required при безопасном checkpoint. При lost admission ACK связь с run ищется через drained gateway admission, но чтение DTO не выдаёт вычисленную связь за новую сохранённую attempt revision. Run/recipe/clientMessage/binding identities должны совпадать; terminal label не скрывает dispatching/recovery_required/awaiting_approval native operation или исчезнувшую run history. Completed/failed child обрабатывается existing terminal pipeline: проверяются checks/artifacts, затем следующий step либо bounded retry. Resume не возвращает использованный policy budget и не меняет pins.

`reconcile` остаётся explicit cancellation without replay. `cancel` при lost admission ACK сначала находит durable child identity, затем адресует Stop этому run. Cancel_requested не означает stopped; terminal ACK обязателен, поздний completed report после запроса отмены отклоняется. Неизвестный native dispatch, lease expiry и interrupted step не разрешают continuation. Interrupted/rejected admission можно безопасно отменить при наличии доказательства; новая попытка требует отдельного разрешённого route, не скрытого replay. Восстановление неизвестного native процесса посредством пользовательского утверждения или изменения permissions не добавлено.

Recovery decisions сохраняются атомарно с exact command receipt и execution. Поля history: action/time/reason/checkpoint/runId/childState; максимум128 записей, reason до2000 символов, history не очищается автоматически. Достигнутый лимит явно отклоняет ещё одно recovery decision. CAS/epoch/conflicting replay сохраняются. Queue projection после resume возвращается в running без повторного admission; physical workspace reservation удерживается всё время recovery.

Restart восстанавливает binding metadata, но broker process ещё не квалифицирован: resume теперь вызывает existing prepareBinding для exact сохранённого binding и затем eligibility. Новая dependency seam `startLocalService(...,{createRecipes})` позволяет fixture контролировать ticks; production default остаётся прежним automatic recipe scheduler. Это constructor injection внутри процесса, не HTTP setting или пользовательский bypass.

Runbook: открыть execution history → проверить checkpoint/child state и session evidence → «Продолжить по подтверждённой точке» либо cancel/reconcile. При policy/artifact/root/scope drift действие отказывает; при unknown outcome ownership остаётся удержанным. Выполненные записи и file effects не откатываются кнопкой Cancel. Повтор исходного запроса после lost ACK использует exact прежний key/payload. Outcome не выставляет Task Done автоматически.
