## Реализованный контракт

`apps/local-service/src/decisions/service.mts` — единственный response owner для S22 и legacy `/runtime/approve` в S09. Public DTO находится в `packages/contracts/decisions/decision.ts`; UI — `apps/web/src/features/decisions/DecisionBoard.tsx`. В primary navigation добавлены Decisions/Решения. GET `/projects/:id/decisions`, GET detail, POST create и POST `/:decisionId/respond` требуют прежние pairing/project/CSRF boundaries. List имеет kind/state filters и bounded pagination; snapshot также показывает policy budget/enforcement, active runs, recipe stop/checkpoint и queue wait reasons через существующих владельцев.

Плановая идея использовать `approval` entity уточнена после RED: существующий `assertIdle()` считает все pending approvals runtime locks. Поэтому durable решения и receipts — private `settings` category `paos_decision` / `decision_receipt`. Generic commands не разрешают settings, а generic reads не выдают private settings/run/approval. Обычное редактирование Task не блокируется продуктовым вопросом. Internal root identity, authority/scope hashes и persisted dispatch receipt не входят в public Decision DTO.

Ответ локальному clarification/product request только записывает выбор/текст владельца. Он не применяет proposed diff и не разрешает runtime command. Runtime request создаётся только из authority-owned snapshot/operations; client не может изготовить такой request. Source session link ведёт к исходной сессии; её inline pending request содержит тот же decisionId. Сохранённые choice/answer явно видны после reload. Legacy session product comments сохранены в исходной истории, coverage note не выдаёт их за мигрированные decision records.

Каждое решение содержит frozen task scope, источник, expiry, proposed/observed/unavailable diff, coverage-qualified evidence и append-only history до64events. Лимит5000records/project, authored TTL60..604800секунд, body8k, diff64k, list50/max100. Автоматической очистки истории нет. Native file permission changes — proposed до исполнения; future command diff честно unavailable, terminal file/check receipts — observed с partial coverage. Доставка ответа (`intent_persisted`, `response_sent`, `acknowledged`) отделена от результата native operation.

SQLite `decisionCommand` — доверенный internal transaction fence, недоступный generic HTTP commands. Он проверяет decision revision/pending, authority epoch, root identity, semantic Task scope и expiry непосредственно при commit. Production использует текущие часы; injectable validationTime доступен только trusted test seam. App gateway повторно проверяет TTL/generation/lease после awaited authority/broker calls, а command start ещё раз проверяет expiry/lease перед native execute. Истёкший request не выдаёт grant/effect даже при истечении во время ожидания.

Intent и exact-key receipt сохраняются до dispatch. Потерянный response ACK допускает повтор исходного запроса без второго effect; changed payload с тем же key конфликтует. Same choice из второго UI после resolved возвращает прежний результат; противоположный ответ отклоняется. Crash/unconfirmed intent переводится в outcome_unknown без automatic replay. Успешный snapshot без прежней pending identity помечает её stale/expired; snapshot failure не считается доказательством завершения. App durable operation records дают историю независимо от того, открывалась ли pending карточка. Для native/API история ограничена наблюдёнными запросами; полнота невиденных provider events и exactly-once arbitrary crash не заявлены.
